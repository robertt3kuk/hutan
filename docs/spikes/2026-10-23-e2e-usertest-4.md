## New findings

### Major
- **F1. Daemon popover's *Start* button is dead where the bottom dock's resize handle lies.** Steps: Problems dock open (⌘⇧M), `hutan daemon stop --stop-sessions`, click `○ Stopped · Start` in the status bar, click the middle of the banner's *Start* (≈ 422,616). Expected: daemon starts. Actual: nothing; an orange 4 px bar spans the centre pane at the dock's top edge (the dock splitter shows its hover state *above* the popover and takes the click). Clicking the button's upper edge (y 603) works. Evidence 18b, 22a, 22b; `pgrep hutand` empty after 8 s. Area: workbench z-order/hit-testing (splitters vs popovers). [INFERENCE] likely affects any popover/menu overlapping a dock edge.

### Minor
- **F2. `Stopped · Start` is not one click.** It opens a popover with two more Start buttons ("Daemon stopped — Start it to reconnect" and "Start daemon"), while the terminal also shows a "Daemon stopped [Start]" overlay drawn over the first terminal line and "The daemon is stopped" at its bottom. Four places say the same thing. Sidebar rows keep `3m` ages/counts as if live. (16b, 17b)
- **F3. After a stop/start, a big recovery card "hutand restarted just now (it was stopped)" + per-session top banners + the open daemon popover stack up** (19a). Heavy for a user-initiated stop.
- **F4. Right-click rail icon vs empty rail** give different menus (panel menu vs checklist); the checklist has no hint it exists, entry `Reset layout to Custom` reads as a no-op (resets to the preset you are editing). Checkmarks are barely visible. Items are in arbitrary order. (64, 65)
- **F5. Undo after closing a split** reopens the session as its own tab (not back in the split) and shows "hutand restarted just now. 1 session: 1 shell respawned" although the daemon did not restart (50b).
- **F6. Request toast text changes after ~1.5 s** from "Claude Code asks to edit: src/lib.rs" to the generic "Claude Code is waiting for you" (two intents replacing each other) (93-req-1 vs 93-req-3).
- **F7. Tab dot clipped**: the attention tab sits at the edge of the scrolled tab strip and its dot/⚠ is cut (93-req-6). Tab strip shows no overflow hint (only a faint `⋯`).
- **F8. Unread dot on session rows is ~3 px, amber, sits below the text baseline outside the icon column** (82, zoomed /tmp/dot.png). Easy to miss and looks like a glitch.
- **F9. Zoomed split (⌘⇧↩) has no visible cue** (tab still `⊞ 3`) (44).
- **F10. Stale tooltip after rail reorder**: hovering the new first icon (Changes) showed "Files" (67).
- **F11. Status bar branch vs tab**: with the feature worktree terminal as the active tab but not focused, the bar says `acme-api · ⎇ main`; it said `feature/login` when that session was focused (05 vs 03). Also Files/Changes scope is the project, so the worktree is never "the container"; the brief's "worktrees as containers" is only a sub-row, `⌃⌥↓` skips it.
- **F12. Daemon-started app launch**: `hutan daemon start` launched `hutan-desktop` by itself (as designed, M6-D) so `open -n --env HUTAN_HOME=…` printed "already running"; the app did use the right home (lsof). Worth knowing for testers; no fix needed.
