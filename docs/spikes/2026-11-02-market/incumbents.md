**Deltas to §2.9's Claude rows** (docs read 2026-11-02):
- Agent view docs now say *replying from the peek panel does not answer a permission prompt or MCP/sandbox dialog* — it "waits in the queue"; you must attach with `→`. For a question **without** predefined choices the empty reply box can show a **suggested reply**, `Tab` fills it ([agent-view](https://code.claude.com/docs/en/agent-view)). This is the first incumbent analogue to "suggested answers", but the suggestion comes from the session itself, not from a supervisor.
- New doc page [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) (see §2.1) — the closest thing to Mawas→agent messaging, with an inbound `accept | hold | refuse` control and an approval dialog. Not in §2.9.
- Claude Code 2.1.316 (2026-10-31) / 2.1.314 (2026-10-30) notes ([changelog](https://code.claude.com/docs/en/changelog)) contain no new supervisor feature; only `/config` agent-view wording (2.1.314) and agent-view input fixes (2.1.311–2.1.312). Cloud-session items: form card for MCP requests, "Catching up…" line on Remote Control resume (2.1.316).
- **Cost controversy (HN, ≈2026-10-29, "4d ago" on 2026-11-02):** a gist claims Claude Code "regularly sends each background agent's transcript to its model", ≈8–16% of tokens by two commenters' estimates; unverified by me, and it concerns subagents/status labels, **[INFERENCE]** probably the same summary mechanism that writes agent-view rows ([HN 50284255](https://news.ycombinator.com/item?id=50284255)). Anthropic's doc confirms rows are written by a Haiku-class model at each turn end and "every few minutes" during long turns, billed to the user ([agent-view § Row summaries](https://code.claude.com/docs/en/agent-view)).

## 2. Per product

### 2.1 Anthropic — Claude Code (agent view · Projects · agent teams · cross-session messaging)
Dates: agent view 2026-05-11; Projects beta 2026-09-17; agent teams experimental (undated in docs); changelog current to 2.1.316 (2026-10-31).

| Aspect | Facts |
|---|---|
| **What the supervisor view shows** | *Agent view* ([doc](https://code.claude.com/docs/en/agent-view)): one screen of every background session across all projects (`--cwd` narrows), rows = name, one-line summary, age; states Working / Needs input / Idle / Completed / Failed / Stopped; sample grouping Pinned / Ready for review / Needs input / Working / Completed; PR chip `#N` coloured yellow (checks/review pending or failed) / green / purple (merged) / grey. Interactive sessions in other terminals don't appear until backgrounded (`/bg`, `←`); subagents/teammates are not separate rows. *Projects* ([doc](https://code.claude.com/docs/en/claude-projects)): **Overview** pane groups threads Ready for review / Waiting on you / Working / Landing / Idle / Resolved, plus Library, Pull requests, Scheduled tasks tabs; a dot on the Overview button when a thread waits. |
| **Attention & approvals** | Peek (`Space`) shows the exact question and `waiting 3m`; reply joins the session's queue; **permission prompts/dialogs must be answered by attaching**. Footer `← 2 agents` counts waiting sessions; terminal tab title `2 awaiting input · claude agents`; notification via terminal channel + `Notification` hook types `agent_needs_input` / `agent_completed`. Projects: desktop-app notifications for thread error/needs-input/coordinator post; *browser has only the dot*; "Telling Claude in the project conversation to go ahead doesn't reach" a thread's approval — it is answered inside the thread ([Projects § Unblock](https://code.claude.com/docs/en/claude-projects)). |
| **Cross-agent coordination** | Cross-session messaging (v2.1.224+): `ListAgents` + `SendMessage`, you can `@session-name`; local over a per-session Unix socket (never via Anthropic), other machines/cloud via Remote Control. **A message "can't approve anything", can't change config, commands in it are plain text; the receiver's own permission prompts still fire.** Inbound `crossSessionInbound = accept | hold | refuse`; default decided by permission-mode class (bypass↔bypass only); `hold` opens an approve/deny dialog showing sender + preview, expiring after `dialogExpiry` (default 5 min); `notify_when_idle` = one notice when a session next idles (12 h cap). ([doc](https://code.claude.com/docs/en/cross-session-messaging)). Agent teams (experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`): lead + teammates, shared task list with dependencies, mailbox JSON per agent, `TeammateIdle`/`TaskCreated`/`TaskCompleted` hooks as gates ([doc](https://code.claude.com/docs/en/agent-teams)). Note from that doc: a plan-mode teammate's plan is **auto-approved on arrival unless you changed its mode**. |
| **Review of output** | PR chip colours; `/code-review` findings card in Desktop/web (2.1.316); `/ultrareview`; Projects thread card buttons *Resolve conflicts / Fix CI / Address comments / Merge it / Review PR / Create PR*; new cloud threads watch their PR with auto-fix on ([Projects § Review](https://code.claude.com/docs/en/claude-projects)). No per-turn packet with warning signs found. |
| **Digests / notifications** | Per-session/per-thread events only; recap posted when you **attach** (model-written). No cross-agent "while you were away" digest found. Scheduled work: `/loop` sessions in agent view (countdown shown), cloud scheduled tasks/routines from Projects. |
| **Memory** | Projects: project memory files (`MEMORY.md` index read by every cloud thread), instructions ≤ 16,000 chars, Library; "the conversation works from recent messages, recent threads, and project memory rather than its full history" ([doc](https://code.claude.com/docs/en/claude-projects)). Thread-on-your-computer starts with instructions but **not** memory files. |
| **Permission / safety** | Projects limits are soft: "instructions Claude keeps to, not enforced settings, so a thread limit you give this way isn't a hard cap". Cloud threads default to **auto mode** (classifier) and ignore repo `.claude/settings.json` permission rules. Agent view sessions inherit permission mode with a "never more permissive than the source" rule; bypass is ignored if consent isn't in user settings. `--safe-mode` row line. Worktree isolation for background sessions (`worktree.bgIsolation`). |
| **Local vs cloud** | Agent view = local only, "stop if the machine shuts down", usage "roughly ten times as fast" with ten agents. Projects = cloud threads by default; "Work locally" via Remote Control (laptop must be awake). |
| **Pricing** | Agent view: Pro, Max, Ultra, Team, Enterprise, API (research preview) ([post](https://claude.com/resources/articles/agent-view-in-claude-code)). Projects: **Pro/Max/Ultra only, not Team/Enterprise yet**. Pro $17/mo annual ($20 monthly), Max $100 (5× Pro), Ultra $200 (10× weekly) ([pricing](https://claude.com/pricing), read 2026-11-02). Coordinator + threads default to Opus; "projects can reach usage limits faster" ([blog](https://claude.com/blog/projects-redesigned)). |

Docs updated within ~2 weeks of 2026-11-02 ([orchestration](https://docs.warp.dev/platform/orchestration/), [managing](https://docs.warp.dev/platform/managing-cloud-agents.md)). **Agent Management Panel** + Oz web app Runs page (mobile-capable) with statuses Working / **Blocked** / Failed / Success / Canceled, filters by source/day/creator/status; **parent→child orchestration** (one level deep): *orchestration pill bar* above the agent header shows each child with a live badge; durable message bus per agent with a global sequence number ("parent never observes SUCCEEDED before the message that produced the result"); children can run Claude Code or Codex harnesses. `/orchestrate` and `/plan` **require explicit approval of the whole fan-out config** before any child launches. **In-app notifications fire on the parent only** (matches Hutan's "never one per agent"). ### 2.10 JetBrains — Air (Junie)

## 3. Cross-cutting observations (dated, with sources above)

1. **Vocabulary has converged**: Needs input / Working / Ready for review / (Landing) / Idle|Inactive / Done|Resolved appears in Claude, Copilot, Codex (`Needs you / Working / Ready / Inactive`), Warp (`Blocked`), Cursor (`In Progress / For Review / Queued`), Devin (Kanban). Hutan's reducer already matches.
2. **Approval fatigue is attacked from the other side**: Codex auto-review, Claude auto mode (cloud threads default), Cursor Projects auto-allow of machine/environment placement (admin setting, 2026-10-12), Antigravity learned grants, Zed OS sandbox. Nobody found ships a *suggest-only* supervisor over a human queue.
3. **Multi-vendor boards are no longer unique**: Devin Desktop (ACP), Zed (ACP + terminal threads), Warp (Claude Code/Codex harnesses), JetBrains Air (ACP), Copilot Agent HQ. What none of them is, from what I read: daemon-owned PTYs for *unmodified* TUI agents with a supervisor that says "exact" vs "state only".
4. **Supervisor-as-agent exists only vendor-internal**: Claude/Cursor/Copilot coordinators and Devin's coordinator drive *their own* workers in the cloud; Amp's Puck is the nearest to Mawas (always-on, voice, MCP, Slack) but manages Amp threads. Warp's parent/child is the only one spanning harnesses.
5. **Phone control is table stakes**: Claude Remote Control, Copilot GitHub Mobile, Antigravity Remote Control, Cursor iOS/Slack, Amp iOS/Android (2026-10-27), Codex phone approvals.
6. **Provenance of decisions is the open wound** (Cursor forum teardown; Claude doc's "limits aren't enforced"; Claude hidden-summary cost controversy).
7. **Cloud billing is arriving**: Copilot sandbox billing from 2026-11; Amp orbs per hour; Claude/Cursor Projects burn quota faster. A local-first story has a price argument.

## 5. What this means for Hutan

**Positioning (differentiate).**
1. *"The category is Projects; Hutan is the local, vendor-neutral, honest one."* Cursor/Claude/Copilot Projects are cloud-first, single-vendor, model-narrated. Hutan's board (0.3.5 *Now* tab) already has the same groupings but is built from daemon state with *exact / state only* labels. Lead the demo with the three things nobody has: (a) a board that mixes Claude Code, Codex, OMP **and a raw terminal agent** with honest completeness; (b) suggest-only supervision (*Mawas suggests: … Use / Dismiss*); (c) per-agent grants showing the whole message. Keep the "zero model tokens for the board and Catch up" line, **but** present it as a design property, not as proof that Anthropic overbills — the HN figures are unverified.
2. *Supervisor outside every harness.* Only Warp's parent/child spans harnesses, and Devin/Zed/JetBrains share boards via ACP without a supervisor agent. Hutan's Mawas = the only one found that is (i) local, (ii) cross-vendor, (iii) permissioned per target. Say so in the demo; avoid claiming "only" in public copy until the other ~12 products in `docs/spikes/2026-10-21-competitor-ux/` and the other market streams are cross-checked.
3. *Web-off guard is a genuine lead.* No incumbent documents it for a manager that reads other agents' transcripts. Zed's own 2026-08-05 post is a ready-made threat story (a contributor PR with a modified `AGENTS.md` telling an agent to upload `$MY_SECRET_API_KEY`) — reuse as the demo's "hostile transcript" scenario, then show Mawas starting with web off and refusing to start otherwise.

**Take (concrete, mapped to Hutan features).**
- **Board / Now:** add **"Landing"** (PR approved/queued) as a group between *Ready for review* and *Idle* — Claude Projects has it; Hutan tasks already have review/merge. Show **age of the wait** (`waiting 3m`) on every needs-you row if not already (Claude does; §2.9 already flagged).
- **Suggested answers:** mirror Claude's rule that *a suggestion never answers a dialog* and that a peeked reply to a permission prompt does not approve it — Hutan already does the right thing (*Use* = your click). Consider the same for **terminal agents** where Hutan can't click on the agent's behalf: say *state only* (already the case).
- **Target-bound grants:** add a **"Allowed targets" list with revoke** — Cursor's Project allowed list (2026-10-12) is the best precedent; also show the *exact commit/message* on merge approvals as Cursor did (2026-09-07). Consider a **circuit breaker**: Codex interrupts the turn after 3 consecutive denials; Hutan's per-turn message cap is analogous — surface "Mawas stopped after N denials" in Recent.
- **Cross-agent messaging policy:** Claude's `crossSessionInbound = accept | hold | refuse` and its "can't approve anything" rule map to Hutan's *never into a waiting agent / never to another Mawas / never to your draft*. Take the **per-recipient setting** (an agent that refuses supervisor messages) and the **`notify_when_idle` subscription** ("tell me when X goes idle", 12 h expiry) as a cheap deterministic Mawas feature on top of `agents_activity`.
- **Provenance in Memory:** Cursor's field report (decisions dropped, "defaults accepted" never accepted, no *who decided*) argues for **`decided_by: user | agent | mawas`** and append-only entries in the Mawas **Memory** tab. Mawas's labels (*from Mawas · sent with your approval*) already point there; extend to memory.
- **Flow:** Warp's rule "notifications fire on the parent only" = your §2.8 "never one per agent"; Amp's **snooze until I'm needed** (ends when approval is needed) is a good *Focus* companion: snooze an agent's non-urgent noise until it needs a human.
- **Review packet:** Amp's *intelligent file ordering* ("files that explain the change first", ≤ 500 files) is a cheap, deterministic add-on for `agent_review`; Antigravity's *Agent Edits / Branch / Uncommitted* tri-view maps onto the packet's changed-files section.
- **Sandbox by default, escalate on request:** Zed's flow (denied by default; agent asks with a reason; grant once / thread / permanent) is the clearest UX for the approvals Hutan shows; Hutan's *Allow once / chat+agent / Deny* already matches.

**Avoid.**
- **Model-written row text billed to the user** (Claude agent view; HN controversy). Keep rows deterministic.
- **Soft limits expressed as prose** ("a thread limit you give this way isn't a hard cap", Claude Projects). Keep Mawas's limits enforced in the daemon.
- **A default auto-approver.** Codex/Claude cloud auto modes solve approval fatigue by moving the decision to another model; Hutan's stance ("she never answers for you") is a differentiator. If fatigue shows up in user tests, answer with **narrower grants + sandbox + fewer prompts** (Zed, Antigravity), not with an approver agent. A reviewer agent is acceptable only as a *suggestion* shown on the card, which is what Mawas already is.
- **Plan-approval short-circuits** (Claude agent teams auto-approve a teammate's plan when its mode is unchanged).
- **Per-child notification storms** — Warp and Hutan already avoid them; keep it.

**Risks / gaps to track.**
- **No phone/remote approvals** while all six cloud-capable incumbents have them. `docs/vision.md` lists remote clients as "later"; the minimum viable bridge is macOS notifications with actions (listed in vision) before any mobile client.
- **Copilot Agent Host + open AHP** and **Devin/Zed/JetBrains ACP** make "any agent on one board" a standard feature in 2027; Hutan's moat is PTY-native terminal agents, supervisor + grants + honesty, and Mac-native performance budgets — keep those front and centre.
- **Anthropic is converging toward Hutan's primitives** (agent view `--json` "for another Claude session that supervises background work", cross-session messaging with hold/approve, Remote Control). Expect a Claude-native "supervisor session" within quarters **[INFERENCE]**; Hutan's cross-vendor and local-honesty angles must be demo-visible.
- **Jules shutdown (2026-12-31)** — no action; note for competitor-slides: single-purpose async agents are being folded into agent managers.

**Demo script hooks (for the later demo).** (1) Open the board with 4 agents from 3 vendors + one terminal agent; point at *exact* vs *state only*. (2) A waiting approval → *Mawas suggests* → *Use* (your click). (3) Mawas wants to message another agent → card with full text → *Allow for this chat and this agent*. (4) Walk away → *Catch up · 2 requests wait for you* (zero tokens) → Recent → Flow. (5) Plant a hostile transcript → Mawas has web off → show the guard. Public contrast lines available from incumbents' own docs: Claude's "replying doesn't answer [a permission prompt]" and "a thread limit … isn't a hard cap"; Cursor's forum "decided by whom?"; Zed's own sandbox post on what is *not* covered.
