# Design: checks — Mawas finds problems in a session or a workspace

Date: 2026-11-02 · User: *"let's make it so he can, per workspace or per session, look, check and find all of this"* (after "do we have checks, insights on sessions?") · Inputs: `docs/spikes/2026-11-02-market/` (pains: false "done", review capacity, attention, cost, semantic conflicts, "the supervisor is a black box"), `docs/spikes/2026-10-28-insight.md` (what each harness exposes; phase B = terminal agents), ADR 0025 (Mawas global supervisor, safety rules R1–R11 in `docs/spikes/2026-10-30-mawas-supervisor.md` §4.3).

## 1. What exists, and the gap

| Level | Today | Missing |
|---|---|---|
| Turn | `agents.review` packet with 7 labelled signs (`crates/daemon/src/agents_review.rs`) | test files edited, tests weakened (`skip`, `#[ignore]`, `.only`, removed asserts), "tests pass" claimed without a passing test command |
| Session | `agent.insight` (context, tokens, tools, files, time; chats only) | anything *across* turns: the same failure again and again, edits back and forth, context pressure, a costly turn, a stall, changes left unreviewed |
| Workspace / all | `agents.stats` (waits, failure clusters, tokens), `agents.activity` | two agents changing the same files, one list of what is wrong where |
| Verification | none — the agent's word | Hutan running the tests itself and keeping the exit code |
| Terminal agents | state only (OSC 7501, hooks, recognised program) | tools, files, tokens (insight phase B) |

## 2. Model: findings

A **finding** is a deterministic, evidence-backed statement about a session or a workspace, produced by a named **detector**. No model call produces a finding; Mawas reads findings, explains them and proposes what to do.

```
Finding {
  id            // stable: hash(detector, session_id, turn_id?, key) — the same problem keeps its id across reads
  detector      // e.g. "tests_weakened"
  severity      // alert | warn | info
  confidence    // exact (from a record: an exit code, a diff line) | heuristic (a pattern; labelled so)
  scope         // workspace_id, session_id?, turn_id?
  title         // deterministic words, ≤ 120 chars, no agent text
  evidence[]    // ≤ 5: {kind: command|file|diff|event|stat|verify, ref (turn/item/run id), excerpt ≤ 200, redacted}
  first_at_ms, last_at_ms, count
  dismissed     // by the user only
}
```

`agents.findings {workspace_id?, session_id?, since_ms?, include_dismissed?, limit?}` (Read) returns findings plus, per session in scope, **coverage** — which detectors ran and which could not and why ("terminal agent: no tool events — install the integration", "Codex: no cost") — so "no findings" is never mistaken for "nothing wrong" (R10). Bounded: ≤ 200 findings, ≤ 24 KiB; text redacted; built on request from the journal, checkpoints, approvals, the state log and the insight reducer (like `agents.review` and `agents.stats`), cached per session by journal sequence. `agents.findings.dismiss {id}` is **UserOnly** (Mawas cannot hide a problem).

## 3. Detectors (v1)

Thresholds live in a daemon `[checks]` table with defaults; every detector has an id, a severity and a confidence.

| Detector | Scope | Rule | Confidence |
|---|---|---|---|
| `done_after_failed_command` | turn | the turn ends successfully after its last test-like command failed (lifted from the review packet) | exact |
| `claimed_pass_without_test` | turn | the final message claims tests/build pass, and no test-like command exited 0 in the turn | heuristic (claim matching) |
| `tests_edited` | turn | test files changed in a turn that also changed non-test code | exact |
| `tests_weakened` | turn | the diff adds `skip`/`xfail`/`#[ignore]`/`.only`/`it.skip`/`@pytest.mark.skip`/`t.Skip`, or removes more assertion lines than it adds in test files | heuristic |
| `snapshot_updated` | turn | snapshot/golden/fixture files rewritten | exact |
| `no_test_command`, `dependency_file_changed`, `file_deleted`, `path_outside_folder`, `secret_like_path`, `large_diff` | turn | as in the review packet today | as today |
| `repeated_failure` | session | the same normalised error or failing command ≥ 3 times | exact count, heuristic grouping |
| `thrash` | session | the same file changed in ≥ 3 turns with net change near zero, or a turn reverting the previous one | heuristic |
| `context_pressure` | session | context ≥ 85 % of the window, or a compaction happened | exact where reported |
| `costly_turn` | session | a turn's tokens ≥ 3× the session median and ≥ 50k | exact |
| `long_wait` | session | the agent waited on the user ≥ 15 min (chat requests; terminal agents from the state log) | exact / state only |
| `stalled` | session | *working* with no event for ≥ 20 min; for a terminal agent "unconfirmed", never "stuck" | exact / state only |
| `unreviewed_changes` | session | finished turns with file changes not reviewed or merged after 4 h | exact |
| `verify_failed` | session | Hutan's own test run (§4) exited non-zero after the agent said it was done | exact |
| `overlap` | workspace | two live sessions changed the same file since either started (worktrees included) | exact |
| `shared_checkout` | workspace | two agents writing one checkout (the existing warning, as a finding) | exact |

Test files and test-like commands are recognised by path and command patterns per ecosystem (Rust, JS/TS, Python, Go, Ruby, Java/Kotlin), shared with the review packet.

## 4. Verification: Hutan runs the tests

`agents.verify {session_id, command?}` (**Mutate**: the user's click runs it; Mawas goes through her gate, target-bound like a message, R3). It runs the project's test command in the session's folder (its worktree if it has one) with the user's login environment, a timeout (default 10 min) and bounded, redacted output (exit code, duration, last 8 KiB), stores the run (`verify_runs`), and feeds `verify_failed` or clears it. The command comes from `[checks] test_command` for the project, else detection (`cargo test`, `npm test`/`pnpm test`/`yarn test` by lockfile, `pytest`, `go test ./...`, `make test`); the card and the CLI show the exact command before it runs. It refuses while the session's own turn is running in the same checkout (it would race the agent) unless forced by the user.

## 5. Surfaces

- **CLI**: `hutan agents --check [--ws W | --session S] [--json]`, `hutan agents --verify S [--command …]`, `hutan agents --dismiss FINDING`.
- **MCP**: `agents_findings` (read, untrusted-data marking), `agents_verify` (gated).
- **Desktop**: a **Checks** tab in Mawas's rail (Now · Recent · Checks · Memory), scoped by the Focus, grouped by severity then session; each row: title, session, confidence label, evidence on expand, *Open* (at the turn), *Review*, *Verify*, *Dismiss*, *Ask Mawas*. The Context panel of a session gets a **Findings** section. *Check with Mawas* in a workspace's ⋯ and a session's ⋯: opens Mawas (Focus = that workspace) with a prepared ask and the findings attached; the user sends.
- **Mawas**: playbook — to check a workspace or session, read `agents_findings`, open `agent_review` for turns with alerts, use `agents_stats` for patterns, propose `agents_verify` when a claim has no evidence; report findings first with their confidence and coverage; never dismiss.

## 6. Terminal agents (insight phase B)

Without tool and file events, most detectors cannot run on a terminal agent; coverage says so. Phase B of the insight spike (OMP extension `insight` reports, Claude Code hook script with tools/files/durations, Codex hooks) feeds the same insight reducer, so detectors that read insight (files, tools, tokens) start working for terminal agents with no detector change.
