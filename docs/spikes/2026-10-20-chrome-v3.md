# Chrome v3 — one agent truth, recoverable docks, semantic icons

Design spike, 2026-10-20. **Recommendation, not implemented.** Scope: desktop chrome and agent visibility; no process/lifecycle changes. Ready to split into implementer briefs. Only this document and its four companion SVGs were written. No app launch, private profile reads, paid calls, or code changes.

## Decision in one sentence

Make **Agents one retained center page with an attention-first list**, make the right Agents panel its **scoped compact projection**, turn ⌘⇧O into a reversible **Agents focus layout**, and make Mawas Today consume the same attention records; use **independent recoverable dock rails** and an **externalizable Phosphor Regular default icon theme**, not hard-coded filename choices.

The primary task is: “Find the agent that needs a decision, understand why, and return to its actual work.” The object is an agent session, with expandable observed child agents—not a Git branch and not a generic terminal. The memorable detail is the explicit reason/action lane, not another grid of colored cards.

## 2. Agent Dashboard v2

### 2.1 One collection, four purposeful surfaces

**Canonical identity:** `(host connection identity, session_id)` is the top-level record; observed children use `(host, session_id, node_id)`. For the current local-only UI the connection identity is the existing connection instance, not a new wire field. A report, ChatInfo and observation root for the same session must join into **one** row. Never count the root both as a session and as an extra child.

**Eligibility:** a visible/non-closed session is an agent session when it has an observation tree, an AgentReport, or ChatInfo. Include Mawas (role label **Assistant**); exclude an ordinary idle shell. Do not treat an arbitrary terminal's unread command completion as proof it is an agent; that remains visible in Projects/Requests attention. Missing placement/model/report does not remove a recognized agent. Closed sessions stay in History, not live Agents.

### 2.2 State, attention and observation are separate axes

Do not compress an approval, process liveness, unread completion and unknown telemetry into one enum. The presentation record carries lifecycle, activity state, attention reasons, observation status and freshness independently.

**Reducer precedence**, shared by all views:
1. Pending actionable approval/question, blocked child/main, unread failure, then task awaiting review/done-unread → attention reasons. Show the highest-priority reason plus `+N`; preserve every reason in details. Approval/question identity comes from the real pending object, not a guessed activity string.
2. Explicit session terminal failure/stop/exit or node outcome wins over obsolete “working” evidence. Child working count can remain distinct if children are still live; never silently rewrite a completed parent into working.
3. Daemon-managed active chat turn → Working; otherwise current authoritative report/root → Working/Blocked/Idle; fallback ChatInfo with inactive turn → Idle. If sources conflict, show the effective state and disclose provenance in details; do not silently prefer the prettiest value.
4. Observation root Unknown with no stronger current evidence → **State unavailable**. It belongs in a distinct **Unconfirmed** section after Working, not Idle/Done. Label “No state report since reconnect” **only when the client knows that fact**; otherwise “This harness has not reported its current state.” Show “Last reported 3h ago” when known. Liveness Unknown → “Process liveness unconfirmed.” The elapsed age is not evidence of progress.
5. Connection lost → retain last good records with **Offline · last confirmed …**. Disable mutations requiring daemon authority, keep local navigation/copy; never show an offline collection as `0`.

A stale timestamp alone must **not** make an idle agent fail, disappear, or become disconnected. Event-driven integrations need not heartbeat while idle. “Disconnected” requires the actual outcome/liveness evidence. No universal 30-second timeout is introduced.

### 2.3 Record and row contract

| Field | Display / source policy |

| Harness, model | Plain secondary text; harness readable even if its mark is missing. Show model as reported, else `Model not reported` in details and omit the empty list column; never invent a model from provider defaults. |
| Project / workspace | Stable location lane, e.g. `hutan / Chrome cleanup`; Home explicitly `Home / Mawas`. Project is attribution, workspace is current container. Task-workspace migration from D-1 is **not** prerequisite scope expansion here. |
| Checkout / branch | Separate `Worktree: chrome-v3` or `Main checkout: master`; branch icon only here. Non-Git: `Folder` in details, no fake branch. Shared-checkout warning retains real placement data. |
| Duration / activity age | Two distinct values: `Running 3m 05s` (known start/end) vs `Updated 12s ago` (last semantic activity). Never use session creation age as agent runtime. Unknown duration renders `—`, tooltip “Start time not reported.” Absolute local timestamp+zone on hover/details. |
| Last activity | One sanitized, ellipsized line of current activity/report, source labeled when needed (`Tool: Reading icons.rs`). Fallback meaningful state reason, not an empty subtitle. Do not copy secret-bearing raw tool arguments. |

**Density:** compact row 64 pt (two 16-pt lines plus 8-pt insets/gap), comfortable 80 pt (three lines); child row 32/40 pt. Inline expanded approval detail is variable height measured by the virtual list. Header 44 pt, filter band 36 pt; keep existing native 36-pt titlebar and 24-pt status bar. 12/11-pt compact text and 13/12-pt comfortable text, inherited UI scale. Icons 16 pt, 28-pt minimum command targets (32 comfortable), not 16-pt hitboxes. One inset spine at 16 pt. Strong reason text and a labeled action distinguish attention rows; hairlines separate rows, no nested card kit. Duration/cost columns use tabular figures and right alignment.

**Responsive columns:** full view ≥900 pt of content: identity/reason, location, harness/model, time, action. At 640–899: location/harness on secondary line, usage details only. Below 640: two-line list; selection expands details below the row, never a squeezed 200-pt inspector. Right panel 240–480 pt uses the same compact row component with optional fields folded into details. These thresholds scale with rem; long labels truncate with full value in accessible details/tooltip, never push action buttons offscreen.

### 2.4 Grouping, ordering, stable updates

Default groups: **Needs you**, **Working**, **Unconfirmed**, **Idle**, **Finished**. Empty groups disappear. Finished collapsed by default, retaining closed/history navigation separately. Within Needs you: explicit approval, question, blocked, unread failure, review, completed-unread; within equal reason use oldest unresolved reason first. Other groups: latest **semantic** activity descending; stable session ID final tie-breaker. Unknown timestamps sort after known values, not as “now.” Child siblings keep start-time/ID order, not re-sort on every tool event.

Optional Group by Workspace makes workspace headings outer groups, with the same state priorities inside; it never creates four horizontally scrolling lanes. Search matches title, harness, model, workspace/project, branch and last activity; no full-transcript indexing is required. Scope and filters stay visible, saved separately for full-page vs contextual panel. Shared scope gives exact matching state/counts. Freeze visual reordering while a pointer is over an action, menu is open, or keyboard selection is being acted on; batch updates and keep the selected domain ID/scroll anchor, then reconcile. A row becoming resolved cannot slide a destructive button under the pointer.

### 2.5 Interaction and keyboard

- Single click selects; double click or **Return / Open session** opens/focuses the session's real Chat/Terminal tab, switching its workspace first. A selected row has visible **Open session** and **More** controls; secondary actions remain available without hover.
- **Approve** is never a row-wide accidental click. `Review request` expands exact request+options; explicit option button sends the existing approval decision. No bulk approve, no automatic “first option” on Return from a selected row. Show submitting state; confirm success only on daemon result/event. Already answered elsewhere removes the actionable control and says so without moving focus to an unrelated row.
- **Answer question** opens its existing question card. **Review changes** opens its checkout diff; missing checkout disables with explanation. **Reveal session**, **Open worktree**, **Show changes**, **Copy session ID**, **Open transcript** are precise menu commands with availability from real data.
- **Interrupt turn** acts only when the harness/session supports it. **Stop session…** names the session, explains work stops, and confirms while live. Stopping a child without a real target/capability is disabled with the harness limitation, never implemented by silently stopping the whole parent. Closing the page/dock never interrupts anything.
- Tab: page toolbar → scope/search/filter → one roving list stop → selected-row actions/details → next region. Up/Down, Home/End, PageUp/PageDown navigate model rows; Left/Right collapse/expand child/details; Return opens. Space expands details (never approval by default). ⌘F focuses local search **only while this surface has focus**. Shift-F10 opens selected-row menu. Escape closes menu/expanded decision first; it does not close the durable center page. ⌘W detaches this page; ⌘⇧O restores the pre-overview layout when in overview.
- Global ⌘⇧J goes to the next attention session as before; no bare-key global agent shortcuts steal terminal input. Every command is an Action exposed in palette/menu and uses live keymap hints. Focused approval Enter conventions apply only inside that actual approval component, not the agent list.
- Accessibility: row name speaks title, state, harness, workspace, reason; metadata is available as fields, children expose expanded/level. Icon-only controls have names and pressed/selected states. Announce newly actionable reasons politely, coalesced; never announce every token/duration tick. Selected and keyboard-focused styles are distinct; no color-only state.

### 2.6 Empty, loading, failure, and privacy states

- First snapshot pending: shaped skeleton rows + `Connecting to hutand…`; no false zero, no animated skeleton under Reduce Motion.
- No agent sessions: **“Your agents will appear here.”** “Start an agent in a workspace, or connect an integration for an agent already running in a terminal.” Buttons **Start agent…** and **Agent integrations…**. Plain terminals stay in Projects. One empty state, not five buckets.
- Only Mawas exists: show **Mawas · Assistant**, even while idle/unconfirmed. This directly fixes the supplied contradiction.
- No search/scope match: `No agent sessions match this view` with visible current scope and **Clear filters** / **Show all workspaces**. Do not offer unrelated terminal creation as the only escape.
- Unsupported observation capability: report/chat rows still show; inline `This daemon does not expose subagents` with update guidance. No made-up tree.
- Offline: cached rows with last confirmed time; **Daemon controls** opens existing reconnect/start controls, never auto-starts work. Permission refusal stays inline with source message; focus remains at the failed command.
- Transcript activity is already visible operational data; this feature does not enable History indexing, scan external transcript directories, send data to a model, or install hooks without consent.

### 2.7 Live ownership, performance and data gaps

**No network polling.** Reuse initial session/tree snapshot + sequenced events; updates enter SessionsStore then a single `AgentPresentation` selector/cache owned alongside store attention. `agent.tree_updated` already updates the client tree (`crates/client/src/store.rs:244-246,387-390`); the desktop emits change categories (`crates/desktop/src/sessions/store.rs:60-75,483-490`). Full page, contextual panel, Today and badges subscribe to relevant categories, not every terminal byte.

P-3 already introduced cached views (recorded at `docs/status.md:10`; cached wrapper `crates/desktop/src/workbench/render.rs:61-74`; explicit theme/density invalidation `crates/desktop/src/workbench/view.rs:1134-1137`). Keep a retained page entity and cached row presentations by session/node revision; do not rebuild trees, formatted activity strings, or terminal preview entities per frame. Virtualize even the first small collection so large collections use the same keyboard semantics. Render visible rows+bounded overscan; cache invalidation includes density/rem, width, theme and icon-theme revision. No terminal live previews in the recommended list. A single visible-only local timer can refresh human durations at one-second granularity, with no IPC; it stops when all agent projections are hidden or no visible duration changes. This is a display clock, not a status poll.

## 3. Alternatives and recommendation

All SVGs are transparent, ≤1000 units wide, semantic theme variables only, illustrative names/data (not live telemetry), system-font fallbacks. They are structural proposals, not screenshots or production Phosphor assets.

1. **A — Attention ledger (recommended):** [mockup](2026-10-20-chrome-v3-dashboard-a.svg). Center list grouped by actionable state, reason/action lane, selected detail below. Scales from one Mawas session to hundreds; predictable keyboard model; preserves space and cannot show four empty columns.
2. **B — Workspace dispatch:** [mockup](2026-10-20-chrome-v3-dashboard-b.svg). Workspace sections with nested agent rows; attention summary at top. Better for people who reason primarily by task/worktree, less immediate global triage. Keep as **Group by Workspace**, not a separate product surface/data model.
3. **C — Two-lane review board:** [mockup](2026-10-20-chrome-v3-dashboard-c.svg). Needs you/Everything else; expandable richer cards. Better at 2–6 sessions, worse with uneven lanes, weak comparison and keyboard order. Do not ship as a default or a permanent second dashboard; alternatives are mutually exclusive designs.

Reason for A over existing kanban: agent state is not a draggable user workflow; users cannot drag a working process to Done. A list makes reasons comparable, tolerates incomplete telemetry, keeps selection stable, and yields width to the terminal. Scope switches and workspace grouping give B's benefit without duplicating the collection.

## 4. Dock collapse model

### 4.1 Left states and commands

| State | Width / content | Recovery |
|---|---|---|
| **Expanded** | Preferred 280 pt, minimum usable 220, maximum 500 or available room preserving 480-pt center; nav labels + Projects page + bottom toolbar. | Titlebar sidebar button, with menu `Compact sidebar` / `Hide sidebar`; drag seam. |
| **Compact** | 44-pt icon rail, 32-pt targets; Search, Projects, Tasks, Agents, Mawas if enabled, More; New session/Settings at bottom. No microscopic project rows or cryptic first-letter workspace icons. Selected destination and attention count stay visible. | Sidebar toggle expands; Projects opens expanded tree; Agents/Mawas open center directly without forcing expansion. Tooltip/accessibility label always supplies name. |
| **Hidden** | 0 pt; no hitboxes/focus stops. Native traffic-light inset stays. | Always-visible titlebar `Show sidebar` button, menu and keybinding. |

**⌘B** is a two-state working toggle **Expanded ↔ Compact** (Hidden → last visible state, default Expanded); it is not a three-state cycle. Full hide is explicit `Hide sidebar` via titlebar button's menu, palette, or Close all docks. The titlebar leading button is always outside the sidebar and after the macOS traffic-light safe region. Its tooltip names the actual next state/key; context menu exposes all three states with checkmarks. The menu and palette provide non-drag paths. Compact is optional: a preference `Collapse sidebar to: Compact / Hidden` lets terminal purists retain old ⌘B behavior; default Compact for new installs, preserve old hidden-toggle preference on migration.

Current model is only a visible bool with width clamping and logical focus fallback (`crates/desktop/src/workbench/model/ops.rs:544-565`); adding three states requires a desktop layout-state migration, not overloaded width=44 magic. Keep last expanded width even while compact/hidden.

### 4.2 Right states and strip placement

**Recommend a vertical 40-pt outer-right activity rail**, outside the right panel body. This resolves the physically impossible requirement of preserving a horizontal full-width strip when the whole right column has width zero. The right panel body is inside the rail, 350 pt preferred, 240 pt minimum, 480 pt maximum (also clamped by center constraints). Order: History, Changes, Requests, Agents, Resources; More for additional movable panels. Each target ≥32 pt with a 16-pt icon, name tooltip, state/count badge that does not replace the icon. The rail's top aligns with content below the titlebar; bottom contains `Collapse right panel`.

- Expanded + **active icon** click → collapse body, remember active panel/width, keep rail. Expanded + different icon → switch panel, keep expanded. Collapsed + **any icon**, including remembered active → expand that panel and focus its last valid target. An icon can be selected-as-last-used without pressed/open styling while collapsed; accessible state distinguishes selected route from expanded body.
- **⌘L** toggles expanded body ↔ rail-only, restoring last active panel. Visible titlebar right-dock button dispatches the same action. Closing a panel via its menu removes that panel from the dock; collapse does not remove it or kill its work.
- Requests attention badge remains when collapsed. New approval does **not** steal focus or auto-expand against an explicit user collapse; announce/toast and let the user choose. Existing reveal-on-approval preference, if retained, must honor the manual-collapse suppression for the current attention burst.
- “Always visible” means normal layouts and ⌘L collapse. Explicit **Hide all chrome / focus preset** may hide both rails; titlebar recovery buttons remain unless the user explicitly enters a minimal full-screen mode, whose menu/key exit remains available. Setting `Right activity rail: Hidden` is an explicit opt-out, not the result of ⌘L. If the dock has no panels, rail can disappear but titlebar `Add panel…` remains.
- Panel reordering/moving uses existing panel identities. A panel moved to another dock leaves this rail, rather than becoming a ghost icon. Right rail has one roving Tab stop; Up/Down move, Return/Space activate, context menu includes Move/Open as tab. No focusable hidden body.

### 4.3 Bottom, focus, responsive collapse, persistence

**⌘J bottom:** toggle bottom body and its text-tab strip together, keeping visible titlebar/status toggle. Standardize **new default keymaps** on ⌘B / ⌘L / ⌘J. Existing Hutan base binds Jump to ⌘J and bottom to ⌘⌥J (`docs/design.md:527-541`): migration must preserve user bindings and old Hutan base behavior, while the new default moves Jump to ⌘P. Show a one-time keymap migration note; never register two competing global ⌘J actions. Bottom minimum 120 pt, default 220, maximum 60% of available height; preserve at least 240 pt center height, collapse when it cannot fit. No automatic bottom opening on incoming output.

**Width policy (default scale, configurable automatic mode):** prefer content constraints to a hard breakpoint alone. Let available center = viewport − effective left width − right rail − expanded right body. Preserve 480 pt center. At **<1180 pt** window width or center deficit: auto-collapse right body first. At **<900 pt** or remaining deficit: compact left. At **<640 pt**, keep compact left + right rail and use dashboard stacked rows; minimum supported normal window 640×480 pt. At larger UI scale multiply content minima/thresholds by the scale factor (physical platform insets excepted). Hysteresis **+80 pt** to restore an automatically collapsed region; restore only when content constraints also pass. Resize never turns an explicitly hidden region back on. Automatic effective state is separate from user intent and is **not written back** as their preset preference. A deliberate user expand temporarily overrides auto-collapse until resize crosses the next threshold; if full widths cannot fit, keep the opposite dock collapsed and clamp the requested panel, never overlay the terminal silently. User can disable auto-collapse.

**Drag-to-collapse:** expanded left seam tracks until 220 pt; 24 pt further inward arms collapse-to-compact, visible snap preview, mouse-up commits (Escape cancels). Expanded right tracks until 240 pt; 24 pt further arms rail-only. Do not persist intermediate illegal widths; restore previous expanded width on reopening. Dragging compact rail inward does not accidentally hide it. Palette/titlebar controls offer equivalent actions. Resize handles remain top-level hit-tested seams (current protection at `crates/desktop/src/workbench/render.rs:1238-1263`). No “drag past minimum” hidden behavior without a visible preview.

**Focus:** on collapsing a body containing focus, close its owned popovers/menus first; store a weak last-valid target, focus last active center pane (or center page root if no terminal). ### 5.1 Direction, weight, licensing, packaging

Use [official `phosphor-icons/core`](https://github.com/phosphor-icons/core), **MIT** ([license](https://raw.githubusercontent.com/phosphor-icons/core/main/LICENSE)). File inventory was resolved from the [official recursive tree](https://api.github.com/repos/phosphor-icons/core/git/trees/main?recursive=1), revision **`2b75f3ad12b420c9504ef05df8d2564a28f8500e`** during this research; pin a reviewed revision in the implementation's asset provenance. All Phosphor basenames below exist in both Regular and Bold at that revision. Do not fetch from forks, npm wrappers, or a runtime CDN.

**Regular at 16 pt** in both light and dark: quiet enough for dense chrome, consistent with native text weight; avoid Thin/Light where scaling loses strokes and avoid Fill/Duotone for ordinary navigation. **Bold is an optional whole-icon-theme variant** for increased-contrast preference, not “selected means bold.” Selected state uses persistent themed surface+foreground, not swapping geometry on hover. Validate Regular/Bold on both themes at 1×/2×, 14/16/20 pt with Increase Contrast; optical legibility is a required implementer visual acceptance, **not claimed proven by this spike**. GPUI Kit's stock icon component uses Lucide (`gpui-kit/skills/gpui-kit/SKILL.md:154-158`); one-family guidance is stronger than a stock default, and Hutan already owns its asset seam, so this is not a reason to reject the user's requested Phosphor.

**Externalization contract:** coordinate with [theme/icon-pack proposal](2026-10-20-theme-packs.md) (ThemePacks owns manifest/storage/security). A pack maps flat quoted semantic keys under TOML `[icons]` to **pack-root-relative SVG paths**. IDs match `^[a-z][a-z0-9]*(?:[.-][a-z0-9]+)*$`; omitted IDs fall back individually to the built-in theme. Unknown IDs warn for forward compatibility. No arbitrary file paths or enum renames required of authors. This section owns the semantic ID list and default artwork choices; it does not define a competing manifest. Color roles are externalizable too: existing fg/muted/border/surface/accent/success/warning/error (error maps existing danger). No agent-specific literal color and no additional required color role.

Current bundle: `Icon::path` resolves `icons/<file>.svg`; `include_bytes!` embeds `assets/icons/*.svg`; `Assets` serves only the enumerated files (`crates/desktop/src/icons.rs:9-35,79-97`), installed via `Application::with_assets` (`crates/desktop/src/app.rs:423`). No separate icon resource build step today: Rust compilation embeds them. Proposed default pack sources remain committed and embedded for offline/recovery use; external packs resolve through the pack service's validated, cached AssetSource with icon-theme revision in cache keys. **Do not require rebuilding Hutan to customize icons.** Cut over all chrome call sites to semantic IDs; remove unused Lucide assets only after every call site migrates, preserving third-party license notices for any artwork still shipped.
