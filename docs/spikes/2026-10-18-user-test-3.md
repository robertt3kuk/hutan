# Hutan hands-on user test — round 3

## Executive summary

**The core experience has improved substantially. No application-wide blocker was observed.** Setup now owns keyboard input and Escape skips it. Cyrillic and emoji work in Settings, the command palette and terminals. Default-mode Copy/Paste and Select All work in the exercised Jump flow. Resources now exposes both mouse menus and a real Kill confirmation; killing only the tester's `sleep 600` worked. Narrow Changes now keeps both Commit all and the small test diff visible.

**Settings is not yet a complete management surface for this build.** Its ordinary desktop preferences generally save correctly: **46 changed settings retained the same changed values after an actual app quit/relaunch and a daemon restart**. Density was checked in a later persistence cycle too. However, notifications, history ingestion/privacy controls, assistant backend/model defaults, harness executable configuration, daemon recovery policy, data/log locations and several advanced settings remain absent or send the user to a configuration file/CLI. History's Settings page controls search defaults, not the indexing switches users need.

The most important new observations are:

1. **Major:** management settings are missing, especially notification policy and assistant/backend/harness/daemon configuration (S1).
2. **Major:** Settings cannot control history ingestion; the similarly named search-default controls are not a privacy switch (S2).
3. **Minor:** Settings keyboard navigation is incomplete: Tab did not leave Search, and Down/Return did not select a dropdown option (S3).
4. **Minor:** no-match Settings search leaves unrelated controls visible without an empty-state explanation (S4).
5. **Minor:** Restart Daemon explicitly promises an empty daemon, but actually reconstructs all six sessions (S5).
6. **Minor:** automatic assistant selection works, but the requested `Automatic · runs <model>` explanation is absent (S6).

No agent Start button or chat Send was activated. Opening Assistant created two idle assistant sessions as scopes changed; the installed OMP ACP backend ran, but no user prompt was sent. No hook install, login/logout, start-at-login enablement, Set/Clear API key or confirmed provider deletion was performed.

## Findings

### S1 — Settings cannot manage several essential daemon/product capabilities

**Severity: major. Probable area: Settings / daemon configuration integration.**

**Steps:** Open Settings with Command-comma. Walk every category, scroll the left navigation through Accounts and Models; inspect General, Assistant, Agent Integrations, Terminal and Layout. Search `notification` and `daemon`.

**Expected:** A user can discover and adjust notification policy, assistant backend/model defaults, daemon lifecycle/recovery and relevant paths from Settings; supported configuration should not require locating/editing TOML or remembering CLI commands.

**Actual facts:** No notifications page or notification toggle exists. Assistant contains only Enabled and global shortcut, not backend/model policy. General has startup/quit behavior but not daemon Status/Restart/Stop, recovery policy or data/log locations. Agent Integrations exposes one auto-install toggle and explicitly tells users to use `hutan integration uninstall` to remove hooks. Terminal environment and custom layout presets show `edit settings.toml` instead of controls. There is no harness executable/arguments/environment, Home-folder or MCP management page. Daemon menu lifecycle actions do exist and work, so this is **not a claim that the product has no UI lifecycle controls anywhere**.

**Evidence:** `E/r3-13-general-compact.png`, `E/r3-16-layout.png`, `E/r3-27-assistant.png`, `E/r3-28-integrations.png`, `E/r3-34-notification-search.png`, `E/r3-35-daemon-search.png`, `E/r3-61-terminal-final-lower.png`; complete category screenshots 13–33 and action inventory in observations.

**Opinion [INFERENCE]:** Missing notification/assistant/privacy management matters more than adding more desktop styling knobs. The displayed “Provider configuration belongs to hutand” wording is unnecessarily implementation-oriented for Settings.

### S2 — History Settings is not history-index/privacy management

**Severity: major. Probable area: History settings / indexing service integration.**

**Steps:** Open Settings → History; inspect sources, roles, range, project and snippets. Open History with indexing disabled; follow its Settings link or search Settings for `index`. Try to enable only Hutan history without reading external harness histories, then disable again.

**Expected:** Settings clearly separates ingestion permission/source paths/retention from search defaults, and permits enabling/disabling only the chosen sources without hand-editing files.

**Actual:** The Settings page contains only search defaults. `index` yields no category. The separate History panel offers Enable, Clear and Rebuild, and says source selection is in daemon.toml. To safely exercise history without external transcript ingestion, this test had to author scratch daemon.toml source switches and use `hutan index enable/disable`. Selecting `[hutan]` in the Settings search-default field is not established as preventing other sources being indexed.

**Evidence:** `E/r3-21-history.png`, `E/r3-36-index-search.png`, `E/r3-100-history-disabled.png`, `E/r3-107-history-search.png`; scratch `home5/daemon.toml`, `index enable` output listing only hutan and final `index disable` in observations.

**Probable explanation [INFERENCE]:** Desktop search preferences and daemon ingestion configuration are separate surfaces sharing the History name. This test did not enable external ingestion to prove a privacy leak; the finding is the missing safe management path and ambiguity.

### S3 — Settings dropdowns and navigation are mouse-dependent

**Severity: minor. Probable area: Settings focus order / shared enum control.**

**Steps:** With Vim disabled, open Settings. Press Tab twice from Search. On Keyboard, click Key bindings to expand Zed/Hutan choices; press Down then Return.

**Expected:** Tab moves focus to navigable categories/controls; arrow/Return changes the focused dropdown selection.

**Actual:** Search remains focused after both Tabs. The dropdown stays expanded with Zed still selected after Down/Return. Clicking Hutan with the mouse does change and save the value.

**Evidence:** `E/r3-45-keymap-menu.png`, `E/r3-46-keymap-keyboard.png`, `E/r3-108-settings-tab-navigation.png`; foreground driver events in observations.

**Boundary:** This is the exercised keyboard path, not a claim that every possible full-keyboard-access setting or native accessibility action fails.

### S4 — No-match Settings search leaves an unrelated page visible

**Severity: minor. Probable area: Settings search / empty state.**
