## Findings

### P2

**F1. File History: the detail pane collapses to one character per line when the centre pane is narrow.** Steps: right dock open (Files panel), window 1280 wide, open `src/util.rs`, ⌘K *Show File History*. Expected: list and detail share the width, or the list shrinks. Actual: list keeps ~430 px, the detail column is ~215 px, the commit title wraps a letter per line and *Open at this revision* is clipped (fh1). Closing the right dock gives the correct layout (fh2). Area: git history view.

**F2. `hutan open <path>` prints the path and opens nothing while the window is up.** Steps: `HUTAN_HOME=… hutan open ~/hutan-scratch/e2e5/repos/alpha/src/main.rs` (also with `:2`). Expected: file tab in the window (help text). Actual: only the path is printed, exit 0, no tab (g1/g2). Area: CLI/daemon→desktop open routing. [one environment; not retried after a restart]

**F3. Changes does not follow Mawas's scope; Files does.** Steps: Mawas · Global tab in front, *Show Folder in Files* → Files says *Mawas · Global*. Open Changes: it shows `beta · main` (the sidebar's active project), not the tracked Home folder that holds Mawas's edits (c1). Design lists only Files/Search/Problems as following Mawas, so this is by design, but it hides the very thing *Track changes* was added for: the user must click Home in the sidebar (which also swaps the centre layout, h1) to see what Mawas wrote. Area: Changes panel scope.

**F4. Keyboard shortcuts stop reaching the app after clicking the Changes tab's History segment.** Steps: Changes tab → click *History*; press ⌘P, then ⌘⇧P. Nothing opens (g3, g4); after clicking empty centre space ⌘P works (g5). [Single repro; could be focus left on a non-focusable element. Not re-tested elsewhere.] Area: focus handling.

**F5. (tester note) `open -n --env HUTAN_HOME=… <bundle>` is refused while the user's own `/Applications/Hutan.app` runs.** Output: "…was already running and so the additional environment variables could not be set" and nothing started. It may also have raised the user's window. Workaround used: run `Contents/MacOS/hutan-desktop` directly with `HUTAN_HOME` set. `docs/process.md`/the usertester profile should say so.

### P3

**F6. Worktree needing trust gives no cue where you are.** *New Terminal in Worktree…* opens a plain terminal; `.env` is already copied, but nothing in the terminal or the sidebar says the setup is waiting. The only hint is *Setup waits for your confirmation · Review…* in the Changes panel (wt4); `hutan wt ls` says "setup needs confirmation". After *Trust and Run* the Setup terminal appears in the sidebar but is not focused; the user must find *Show output*. Works otherwise (wt5, wt6). `.setup-marker` (a file the setup wrote) then shows as a change in Changes.

**F7. Rewind: "Put a note for OMP in the composer" was ticked, but the composer stayed empty** after *Restore 1 file* (w6). Not confirmed whether the note is attached as a hidden chip.

**F8. Mawas shows no model anywhere.** With Mawas on Automatic, the first message starts an agent on the picked model (Sonnet-tier is possible); only `hutan events` shows it. I pinned Haiku in `daemon.toml`. Also the empty state of a Global chat says *Ask Mawas about this project*; the approval card for a write is OMP's raw question form (`value *`, radios, Submit/Decline), and the first Submit click right after choosing *Approve* did nothing (second click worked, w3→w4; not re-tested).

**F9. Sidebar project rows hide the uncommitted count on the active row** (alpha `○2` shows only while another project is active, h2 vs h4). Changes tab titles for two repos are both `Changes · main` (ch2).

**F10. Blame gutter truncates the message to ~7 characters** (`initial…`, `add sec…`) in a 330 px column; no way to see the message except hover (not tested) (g9).

**F11. Changes ▸ History: the commit list is ~3.5 rows tall and the success banner (*Committed … Done*) stays above it** (ch4).

**F12. Light theme: active find match vs others is low contrast** (fl1 pixel values: active (150,118,54) vs other (89,75,42) in dark; light shows both as pale tan).

**F13. Wording:** "1 files in the first commit" (t2 status bar).

**F14. Instructions: the row says AGENTS.md is *Read by … Claude Code* while the Share button is still offered** (beta, i7/i8). Matches `docs/agents.md` (Claude Code 2.1.277+ reads it) but reads as a contradiction. Opening AGENTS.md shows the *Language server for Markdown runs code from this folder… Trust* banner, truncated (i7).

**F15. Memory files:** a `- bullet` appended to a section is kept literally inside the entry text (`Prefer short answers\n- Always answer in Spanish`, me3); `.mawas/` shows as untracked in the Home repository's Changes after the first memory write.

**F16. Automation:** hooks are read only at daemon start (stated); no *Open daemon.toml* button next to the list (s4).
