# Remote hosts and transports — D-3 research and design

**Status:** proposal, not an implementation or accepted decision.

**Recommendation:** accept **D-3: SSH first → direct TLS second → E2EE relay later**. Introduce a transport boundary without changing Hutan’s frame encoding, event sequencing, replay, snapshot rules, or terminal credit-1 pacing. Use **the system OpenSSH executable**, not a Rust SSH implementation, for the first remote transport.

The local daemon remains the default host. A remote host is an explicitly selected execution and storage location—not an extension of the laptop filesystem, and not an implicit synchronization destination.

## 2. Hutan’s existing seam: framing is ready; connection ownership is not

| Area | Current behavior | Required change |
|---|---|---|
| Client stream | Concrete `UnixStream`; handshake and read/write loops use Unix owned halves. | Generic async read/write plumbing. |
| Server authentication | `conn::serve` checks peer UID before handshake. | Keep this check in the local acceptor; pass an authenticated principal into generic serving. |
| Endpoint resolution | Local socket path and local autostart are coupled to dialing. | Typed endpoint configuration; local autostart only on local endpoints. |
| Reconnection | One reconnecting `Connection` owns its thread, state, supervisor, generations, and channels. | Reuse one `Connection` per host. |
| Shutdown UI | Treats disconnect as potentially successful shutdown, then waits for socket-path disappearance. | Separate “request accepted,” “connection lost,” and “termination confirmed.” |
| Daemon watchdog | Disappearing/replaced local socket stops the daemon because the comment assumes nobody can reach it. | Define multi-listener lifecycle explicitly before enabling TLS. |
| Paths and attachments | Paths are read by the daemon. Desktop-selected local paths can currently be transmitted as path strings. | Make the owning host explicit in the client model; upload laptop files rather than reinterpret their paths remotely. |

### Invariants to retain

The actual frame is:

```text
u32 big-endian payload length | u8 kind | payload
```

**The length excludes the kind byte.** The maximum payload is 4 MiB. Kinds remain control JSON, terminal render, and terminal input. Source: `crates/protocol/src/frame.rs:1-24,100-135`.

ADR 0002 additionally requires:

- Major/minor negotiation and capability-gated additive features.
- Epoch-scoped replay and sequence watermarks.
- Subscribe-before-snapshot.
- Credit-1 terminal rendering with latest-state coalescing.
- Bounded outbound queues and disconnect/replay recovery for slow consumers.

Source: `docs/adr/0002-ipc-transport-and-framing.md:18-44`.

A transport adapter must not decode and re-encode these frames.

## 3. Connection methods and tradeoffs

| Method | Advantages | Costs and limits | Recommendation |
|---|---|---|---|
| Local IPC | Lowest complexity and latency; OS peer authentication. | OS-specific endpoint and peer identity handling. | Default; preserve Unix behavior and add Windows named-pipe support through the platform layer. |
| SSH command stdio | No new listening port; inherits known hosts, agents, bastions, enterprise configuration; simple byte stream. | Requires remote proxy binary and suitable SSH command execution; shell stdout pollution must be diagnosed. | **First remote method.** |
| SSH socket/port forwarding | Can reuse local-looking socket plumbing; useful for third-party clients. | Extra listeners, cleanup and forwarding policy; Unix socket forwarding is not the cross-platform seam. | Not the primary desktop path. |
| Direct TLS | Fewer subprocesses; good LAN/VPN/Tailscale experience; usable by future non-SSH clients. | Exposed listener, device credentials, enrollment, revocation and key recovery. | Second, explicitly enabled. |
| E2EE relay | Outbound-only reachability through NAT; future mobile access. | Broker operation, metadata exposure, account/device authorization, cryptographic transport and reconnect complexity. | Later, with a separate security ADR. |

herdr demonstrates SSH command stdio and a local bridge socket; its saved-host checks distinguish an already-running compatible server from bootstrap. Sources: `src/remote/attach.rs:1,53-105,108-138`.

Orca demonstrates a more elaborate alternative: managed remote runtime installation, SSH tunnels, identity verification beyond “port opened,” and stdio fallback. Sources: `docs/spikes/2026-10-18-orca-process-remote.md:38-45`.

Hutan does not need Orca’s entire remote runtime stack to deliver SSH control of `hutand`.

### Recommendation

Use one supervised system `ssh` process per active host connection. Do not initially introduce an OpenSSH ControlMaster owned by Hutan: one persistent framed connection already multiplexes Hutan operations.

This also avoids a Unix-only `openssh` crate blocking Windows. A Windows implementation can invoke installed OpenSSH; executable availability must be reported honestly.

## 5. Concrete transport boundary

### Client model

Proposed types, not existing APIs:

```rust
enum Endpoint {
    Local(LocalEndpoint),
    Ssh(SshEndpoint),
    Tls(TlsEndpoint),
    // Relay is added only when implemented.
}

struct ConnectOptions {
    endpoint: Endpoint,
    expected_host_id: Option<HostId>,
    local_autostart: Option<LocalAutostart>,
    // Existing protocol/capability/reconnect options.
}
```

Make it structurally impossible to apply local daemon autostart to an SSH/TLS endpoint.

Prefer generic stream handling:

```rust
async fn handshake<R, W>(
    reader: &mut FramedRead<R, FrameCodec>,
    writer: &mut FramedWrite<W, FrameCodec>,
    hello: Hello,
) -> Result<Welcome, ClientError>
where
    R: AsyncRead + Unpin,
    W: AsyncWrite + Unpin;
```

For the reconnecting supervisor:

1. Match the endpoint at the dial boundary.
2. Instantiate the same generic connected-session implementation with the returned reader/writer.
3. Keep transport ownership alongside it:
   - Local: socket/pipe handle.
   - SSH: child handle, stdin/stdout, bounded stderr drainer.
   - TLS: authenticated TLS stream.
4. On cancellation, close transport I/O, terminate/reap an owned SSH child, and cancel the existing read/write tasks.

This avoids allocating or copying per frame. A one-time boxed stream is an alternative if generic branching makes the supervisor substantially harder to maintain; it is not necessary to establish the seam.

### Daemon model

Separate authentication from generic framed serving:

```text
Unix acceptor
  -> verify peer UID
  -> AuthenticatedPeer::LocalUser
  -> serve_io(reader, writer, peer, context)

Named-pipe acceptor
  -> verify OS identity / ACL policy
  -> AuthenticatedPeer::LocalUser
  -> serve_io(...)

TLS acceptor
  -> validate certificate + active device record
  -> AuthenticatedPeer::Device
  -> serve_io(...)
```

Only acceptor/authentication modules may construct `AuthenticatedPeer`. A claimed `device_id` or `client.kind` in JSON is not authentication.

The current UID rejection must remain **before** processing a local connection’s hello. Never replace it with an “optional auth callback” whose default permits unauthenticated TCP.

`ConnHandle` gains the authenticated principal. Existing control policy remains enforced; transport authorization is an additional boundary, not a replacement.

### Suggested module layout

Keep this within existing crates; a transport plugin framework is unnecessary.

```text
crates/client/src/
  transport/mod.rs       Endpoint, dial result, ownership
  transport/local.rs     platform IPC + local-only autostart
  transport/ssh.rs       system SSH, child lifetime, stderr
  transport/tls.rs       pinned trust + device certificate
  hosts.rs               host catalog interface
  client.rs              generic framed handshake/read/write
  connection.rs          still one connection/store per host
  supervisor.rs          endpoint-aware reconnect policy

crates/daemon/src/
  listeners/mod.rs       configured listeners and lifetimes
  listeners/local.rs     existing UID check / platform IPC
  listeners/tls.rs       rustls accept + device lookup
  auth.rs                authenticated principal and authorization
  conn.rs                transport-independent framing/session
  host_identity.rs       stable installation identity
  devices.rs             pairing/device administration
  attachments.rs         staged uploads and attachment handles

crates/cli/src/
  proxy.rs               byte-only stdio bridge
  hosts.rs               explicit host/bootstrap commands

crates/protocol/src/
  host.rs                additive handshake identity DTOs
  devices.rs             capability-gated device methods
  attachments.rs         capability-gated upload DTOs
```

Platform IPC and secret storage should reuse the proposed platform layer rather than grow another set of OS helpers.

## 6. `hutan proxy`: exact contract

Proposed invocation:

```text
ssh -T [SSH options] target hutan proxy
```

For a managed installation, use its recorded executable path rather than depending on the remote login shell’s `PATH`.

`hutan proxy`:

1. Resolves the **remote** local IPC endpoint using the same platform resolver as the daemon/client.
2. Connects to an already-running daemon.
3. Copies stdin → socket and socket → stdout with bounded buffers.
4. Writes diagnostics only to stderr.
5. Does not parse Hutan frames, inject a hello, add a ready marker, use line encoding, base64 the stream, or allocate a PTY.
6. Never installs, upgrades, starts, or restarts a daemon implicitly.
7. On stdin EOF, shuts down the socket’s write half and drains pending output with a bounded shutdown deadline.
8. On socket EOF/error, stops the bridge rather than waiting forever for input.
9. Exits unsuccessfully when it cannot connect or bridge.

The remote daemon sees the proxy’s local UID, preserving the existing local authentication model. The SSH server authenticates the remote login user; OpenSSH validates the SSH server.

This means SSH is **account-level access**, not a revocable Hutan device credential. Someone retaining SSH access as that remote user can run another proxy after a TLS device is revoked.

### SSH process policy

Defaults:

```text
-T
-o BatchMode=yes
-o StrictHostKeyChecking=yes
-o ForwardAgent=no
-o ForwardX11=no
-o ClearAllForwardings=yes
-o ServerAliveInterval=15
-o ServerAliveCountMax=3
```

Use a bounded connection deadline. Honor the chosen SSH alias and its `ProxyJump`/`ProxyCommand`; do not attempt to reimplement the configuration parser.

Host creation should distinguish:

- SSH configuration/authentication preparation.
- Explicit trust confirmation of a new SSH host key.
- Noninteractive operational connection.

Never silently use `StrictHostKeyChecking=no`. Never share framed stdin with a password prompt. If interactive setup is required, direct the user through an explicit terminal/setup operation before reconnecting.

Use argv, not a local shell command string. SSH still passes the remote command through a remote shell: quote remote paths with the selected remote-shell rules, and reject unsupported combinations rather than assuming POSIX quoting works in PowerShell. See [`openssh`’s remote-shell documentation](https://github.com/openssh-rust/openssh/blob/master/src/lib.rs).

Drain stderr continuously into a bounded diagnostic buffer, for example 16 KiB retained. Treat it as untrusted terminal/log content. Do not parse localized stderr into authoritative lifecycle facts.

A remote shell printing to stdout will corrupt the frame stream. Report a specific “unexpected bytes before Hutan welcome; check remote shell startup output” diagnostic; do not strip arbitrary bytes until a frame happens to parse.

## 7. Host identity and handshake

### Identity distinctions

Keep four concepts separate:

1. **Host profile ID:** local catalog identity; exists before first contact.
2. **Host installation ID:** random stable UUID generated once per daemon data directory.
3. **Transport authority:** SSH known-host identity, or pinned TLS host authority.
4. **Epoch:** changes every daemon boot; already scopes replay.

A hostname, PID, SSH alias, or boot epoch is not the stable host identity. A UUID is not cryptographic authentication.

Orca makes the same distinction: its installation UUID persists per profile; machine-binding information is a hint, not an identity proof. Source: `src/shared/runtime-host-descriptor.ts:3-18`.
