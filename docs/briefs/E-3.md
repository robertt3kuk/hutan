## Scope
`crates/protocol` (types, version, capabilities, fixtures), `crates/core` only if a shared type is needed, `crates/daemon` (new `fs` service, router classification, watcher), `crates/client` (typed calls), `crates/cli` (`hutan fs ls|cat|write|find|search` and `hutan open <path[:line]>` — print-only without a desktop), docs `docs/protocol.md` § fs, `docs/control.md` classification rows, `docs/architecture.md`.
1. Requests and events exactly as the spike's table, with its bounds (1 MiB chunks under the 4 MiB frame, 64 MiB hard cap, ≤ 8 concurrent uploads with 30 s idle expiry, list ≤ 5000, find ≤ 200 over a lazily built bounded index, search ≤ 1000 cancellable with progress events, ≤ 256 watched paths per connection, `fs.changed` coalesced ≥ 50 ms and ≤ 500 changes with `overflow`).
2. Confinement: roots are the workspace/project roots the daemon tracks; `picked` paths allowed as `context_file::read_picked_file` does; `../` and symlink escapes refused; writes atomic (temp in the same dir, fsync, rename, mode preserved), refused under `.git/`; `expect` version precondition → `conflict` with `data.current`.
3. `origin` attribution on `fs.changed`: `self` (suppress echo of this client's own `write_id`), `agent` (heuristic from journal `FileDiff` within a window → `tool_call`, else a working agent session whose cwd contains the path → `session`), `external`.
4. Classification: reads are `read`; `fs.write.*` is **mutate** and agent-originated writes go through the `[control]` approval like other mutations (`docs/control.md`).
5. Watchers: one `notify` watcher per root only while a client holds interest; `target/`, `node_modules/`, `.git/` internals filtered before the bus.

## Acceptance
- Tests (daemon `tests/it/`, protocol roundtrip + golden): `../` and symlink escapes refused, `picked` allowed; write precondition → `conflict`; a 6 MiB file round-trips in chunks; own write not echoed (`origin: self`); a `FileDiff` in a chat then a file change → `origin: agent` with the tool call; coalescing and `overflow`; agent-originated `fs.write` requires approval; unbounded channels absent (bounded queues everywhere).
- CLI smoke on a temp `HUTAN_HOME` + temp repo: `hutan fs ls`, `cat`, `write` (conflict path too), `find`, `search`, `open`.
- `just check` green (machine-wide lock). Commits: protocol/types first, then daemon, then client/CLI/docs; messages end `(E-3)`.
