## Scope
- `crates/lsp_client` (no GPUI, no daemon types; depends on `core` only if needed): `Content-Length` codec with a frame size cap; request/response correlation with per-request timeout and cancellation (`$/cancelRequest`); bounded outgoing and incoming queues (a slow server never grows memory; overflow policy documented and tested); server-initiated requests answered (`workspace/configuration`, `window/workDoneProgress/create`, `client/registerCapability` minimal); notifications fan-out (`publishDiagnostics`, `$/progress`, `window/logMessage` bounded); `initialize`/`initialized`/`shutdown`/`exit` lifecycle with a kill fallback; capability negotiation incl. `positionEncoding` (prefer UTF-8, fall back to UTF-16 with conversion through `hutan-buffer`'s metric); a typed request subset (hover, definition, references, completion, documentSymbol, formatting, rename prepare/apply, codeAction) — types only and round-trip tests; document sync with **coalescing**: a burst of changes to one document becomes one `didChange` (incremental when the server supports it, full otherwise); server state machine `starting → indexing → ready → failed/stopped` driven by `$/progress`; restart policy (exponential backoff, N failures in a window → `failed`); child-process reaping incl. descendants (rust-analyzer's proc-macro servers), RSS of the process tree readable for Resources.
- Types: `ls-types` (verify it is a drop-in for `lsp-types 0.97`; if not, use `lsp-types` and say why), dependency added to root `[workspace.dependencies]`; cargo-deny green.
- Fake server: `xtask fake-lsp` (or a `[[bin]]` in the crate's tests, following `xtask fake-codex`) driven by a script: answers initialize with chosen capabilities, emits diagnostics after `didOpen`/`didChange`, progress, hover/definition replies, can crash on cue, can hang, can flood.
- Docs: `docs/architecture.md` crate list; `crates/lsp_client` module docs.

## Acceptance
With the fake server: initialize → diagnostics → hover → definition flows; a crash restarts with backoff and ends `failed` after the limit; a hung request times out and is cancelled; a flood of notifications never grows the queues beyond their bound (test asserts the bound); a burst of 100 changes in one tick sends one `didChange` whose result equals the final text; UTF-16 positions convert correctly for a line with emoji and CJK; dropping the client kills the server and its children (no process left — assert via pid); a grep-style test fails on `unbounded` in the crate as in other crates. `just check` green; commit per step, messages end `(E-11a)`.
