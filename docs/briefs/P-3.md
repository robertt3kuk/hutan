# P-3 — make the desktop feel fast (narrow invalidation, cached views, cheaper rows, faster flood)

Owner: implementer. Crates: `desktop`, `terminal` (emulator flood path). No protocol changes. Source: `docs/spikes/2026-10-18-perf-lag.md` (measurements, samples, ranked causes) — read it first; Orca's technique to copy is **stable identity + narrow invalidation** (memoized rows/views, stable callbacks).

Baseline (Apple M4, release, `docs/spikes/2026-10-18-perf-lag.md`): idle desktop 0.5 %; B5 flood typing p95 55.6 ms (echo→prepaint 55 ms, daemon echo 0.13 ms); B9 filter p95 15.6 ms / 22.5 ms incl. display; B7 scroll work p95 5.1 ms; flood: daemon ~100 % of a core (vte + settle/spill), desktop 10–13 %.

## Change

1. **Cached view boundaries** (rank 1): split the root render (`workbench/render.rs:70-104`) so docks (left sidebar page, right sidebar panel), each center pane's terminal/chat view, titlebar and status bar are separate views drawn through `AnyView::cached` (or equivalent entity boundaries) and re-rendered only when their own entity notifies. Audit what each reads (focus, hover, window active, theme/density, regions/probes) and pass those in explicitly or subscribe narrowly; keep the GPUI test probes (`Region`) working. Verify with the sampler that filtering the left list no longer runs `HistoryPanel::render_row` and that terminal output no longer lays out the sidebars.
2. **History rows** (rank 2): no `SessionItem` clone per row (`history_view.rs:1041`) — `Arc` the immutable row data; cache formatted meta/age/tooltip strings per item revision and minute bucket; hoist home dir/time zone/settings reads out of the per-row path (`:1052-1058, :1203, :1215`).
3. **Narrow invalidation** (rank 4): `SessionStore::apply_state` (`sessions/store.rs:276-334`) emits granular change kinds (session set changed / one session's metadata / attention / workspaces) and does not notify when nothing changed; the sessions panel rebuilds its structural entries only on structure changes (`panels/sessions.rs:241-244, 620-638`); History ignores store notifications unless connection or scope changed (`panels/history.rs:194-213`); `workbench/terminals.rs:735-748` does the same.
4. **Flood throughput** (rank 3): in `crates/terminal/src/emulator.rs` merge the three per-slice scans (`:307-323`) into one state-aware pass, settle once per read batch instead of per slice (`:707-710`), make history spill (`:1008-1022`) convert rows in bulk (no per-cell work where the row is plain), keeping bounded scrollback, escape ordering and resize invariants (existing emulator tests + new ones).
5. **Presentation while typing**: check whether GPUI's inactive-window throttling (`gpui/src/window.rs:1813-1847`) or our own frame scheduling delays echo; make sure a terminal that receives output while focused requests a frame immediately (one frame, not every byte).
6. **Idle**: hidden panels/panes do no work (no timers, no blink) — audit timers again after 1–3; the CVDisplayLink fix (GPUI patch) is out of scope here — write a short note in docs/perf.md with the exact GPUI change needed.

## Measure (before/after, release build, same machine; record in docs/perf.md)

`just bench` scenarios B3, B5, B7, B9 (+ the flood desktop/daemon CPU from the perf report's manual method). Targets: B5 p95 ≤ 25 ms when the window is active; B9 filter incl. display p95 ≤ 18 ms; sidebar interaction samples contain no History/terminal layout; daemon flood CPU down ≥ 20 % at equal throughput; no regression of idle.

## Tests

Keep all existing GPUI tests green; add tests that a store notification which changes nothing does not re-render the sessions panel / History (render counters behind `cfg(test)` or a debug probe), and emulator tests for the merged scan and bulk spill (byte-identical grid/scrollback vs the old path on recorded floods).
