# MW-2 — Mawas memory: curated, revisioned, approved; context snapshot per backend

Owner: implementer. Crates: `protocol` (authorized only for the memory contract below), `storage`, `daemon`, `client`, `cli` (incl. `hutan mcp`), `desktop`, docs. Read ADR `docs/adr/0017-mawas-local-meta-harness.md` (decision 3 "memory", decision 4 safeguards) and design `docs/spikes/2026-10-18-meta-harness-assistant.md` §4 (memory service: 4.1–4.4) and §5 (what each backend supports for injection). MW-1 (merged `74542d8`) gives grants, Mawas origin, approvals, the Home page and Settings → Mawas; reuse them.

Goal: Mawas remembers what the user approved — about the user (profile), environments/projects (fact) and per-workspace decisions (note) — locally, with history, and nothing the model writes is "saved" without the user's approval and a daemon receipt.

## Change

1. **Storage** (next migration after 12): `memory_entries(id, scope_kind CHECK(global|workspace), workspace_id NULL, category CHECK(profile|fact|note), current_revision, state CHECK(active|archived), created_ms, updated_ms)`, `memory_revisions(entry_id, revision, body, content_hash, provenance_json, author_kind CHECK(user|agent), approval_id NULL, operation_id UNIQUE, created_ms, PK(entry_id, revision))`, `memory_proposals(id, scope_kind, workspace_id NULL, operation CHECK(create|update|archive|restore), entry_id NULL, expected_revision NULL, category, body, provenance_json, state CHECK(pending|applied|rejected|conflict|cancelled), origin_chat_session_id NULL, created_ms, resolved_ms NULL)`, a per-scope revision counter, and `memory_snapshots(id, chat_session_id, backend, manifest_json, rendered, content_hash, created_ms)`. Revisions immutable; archive/restore add revisions; updates require `expected_revision` (mismatch → proposal state `conflict`, visible); one transaction applies + writes receipt + bumps scope revision; duplicate `operation_id` returns the original receipt. Session-scope notes are out of scope.
2. **Rules** (daemon, fail closed): body ≤ 2 KiB; bounded totals (setting `assistant.memory_max_entries`, default 200; rendered snapshot ≤ 8 KiB, deterministic order: profile, then fact, then note; newest revision first inside a category; truncation is explicit in the manifest). Redaction before persistence: anything `hutan_index` redaction or the gateway secret detector flags as a credential is **refused** with "Memory is not a secret store" (no silent masking). Provenance is stamped by the daemon (user-entered / chat session + turn), never taken from the model. Model-written entries are labelled **inferred** until the user edits or confirms them.
3. **Protocol 0.32, capability `memory`** (golden fixtures appended at the END of the lists; `docs/protocol.md`):
   - `memory.list {scope?: global|workspace, workspace_id?, category?, include_archived?}` → entries with current body, revision, category, scope, inferred flag, provenance summary.
   - `memory.history {entry_id}` → revisions.
   - `memory.write {operation_id, scope, workspace_id?, category, body}` / `memory.update {operation_id, entry_id, expected_revision, body}` / `memory.archive|restore {operation_id, entry_id, expected_revision}` → receipt `{status:"applied", operation_id, entry_id, revision, scope_revision}`. **User-only** (agent origin → `forbidden`).
   - `memory.propose {...same payload..., op}` (agent-allowed) → `{status:"proposed", proposal_id, applied:false}` and a `control`-style approval that the user answers Approve / Edit & approve / Reject; approval applies the exact reviewed payload against `expected_revision` (not a re-match). `memory.proposals.list` (user-only) and `memory.proposals.resolve {proposal_id, decision, edited_body?}` (user-only).
   - Event `memory.changed {scope_revision}` so clients refresh without polling.
4. **MCP** (`hutan mcp` tools for Mawas): `memory_search` / `memory_list` (reads, free), `memory_propose` (returns `proposed`; text says it is NOT saved until the user approves). No direct write tool for agents. Update the MCP guide.
5. **Context snapshot per backend** (§5.1 matrix): at Mawas conversation start the daemon renders the bounded snapshot of active global + current-workspace entries, stores it in `memory_snapshots`, and delivers it: **OMP** — a daemon-owned private file (0600, under the data dir) passed via the existing append-system-prompt route (never memory text in argv); **Codex app-server** — `developerInstructions` on thread start/resume (typed DTO field); **Claude Code ACP** — first-turn labelled context block in prompt content (system-prompt extension only if the adapter advertises it; otherwise prompt content); **direct providers** — a system message. At later turn boundaries, if the scope revision moved, send a compact labelled delta ("Hutan memory update: added/changed/archived …") as Hutan-added context in the journal, never as user text; never silently omit an archive. Setting `assistant.memory` (default on) disables injection entirely.
6. **CLI**: `hutan memory ls [--workspace ID] [--category ...]`, `add <text> [--category] [--workspace]`, `edit <id> <text>`, `archive|restore <id>`, `history <id>`, `proposals [--approve ID|--reject ID]`, `--json` everywhere.
7. **Desktop**: Mawas Home gets a **Memory** entry point (Today rail link + palette "Mawas: Memory") opening a Memory page (center pane item, one instance): grouped by category, scope filter, add/edit/archive/restore, history per entry, inferred badge, pending proposals on top with Approve / Edit & approve / Reject; a pending memory proposal also appears in Today → Needs you. Settings → Mawas: memory on/off, max entries.
8. Docs: `docs/assistant.md` § Memory (what is stored, what is sent to which backend and how, deletion caveat: archived/erased cannot recall bytes already sent to a provider), `docs/protocol.md`, `docs/control.md` (memory methods and origin rules), `docs/design.md` (Memory page).

## Tests

- Storage: revisions immutable; `expected_revision` mismatch → conflict; duplicate `operation_id` → same receipt; archive/restore history; bounds.
- Daemon: agent-origin `memory.write`/`update`/`resolve` → `forbidden`; `memory.propose` → pending approval, approve applies exactly the reviewed payload, reject never injected; credential-looking body refused; provenance stamped by daemon; snapshot is deterministic and bounded with explicit truncation; delta after a change at the next turn boundary (fake ACP + fake Codex fixtures: OMP file path passed and file 0600; Codex `developerInstructions` present; Claude first-turn block); `assistant.memory=false` → nothing injected.
- CLI: `hutan memory add/ls/edit/archive/history/proposals` round-trip against a temp daemon.
- GPUI: Memory page lists/edits; proposal Approve / Reject from the page and from Today; hidden page does no work.
