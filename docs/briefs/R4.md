# R4 — fixes from user test round 4 (Settings)

Source: `docs/spikes/2026-10-18-user-test-4.md` (findings R4-1…R4-8, evidence paths under `hutan-usertest/scratch/`).

## R4-A (implementer A; crate `desktop` only)

1. **R4-1 (major) modal focus.** After any confirmation/modal in the workbench is cancelled or confirmed (Clear key, integration Install/Repair/Uninstall, Reset page, Revoke all, daemon Stop/Restart, provider Remove …), keyboard focus must return to what had it before the modal opened (the Settings search or the focused control), and typing / ⌘A / Escape work there again. Find the shared modal path (`workbench/modal.rs`, `open_confirm`, `intercept_keystrokes`/setup guard in `view.rs`) and fix it once for all modals: remember the previously focused handle on open, restore it on close (if it is still alive, else the sheet's search when the sheet is open, else the workbench). GPUI test: open Settings → Models → Clear key → Cancel → ⌘A + type "data" lands in the search and filters; same after an integration confirmation and after Reset page cancel.
2. **R4-2 (major) stopped latch.** `SessionsStore::set_daemon_stopped(true)` (explicit Stop) is never cleared when a daemon comes back by any other path (CLI `hutan daemon start`, autostart, another client). Clear it whenever the connection reaches Connected with a new epoch (and in `daemon::Start` when the answer is "already running": reconnect + clear instead of only saying so). Terminals' input gate must follow. GPUI test with a real test daemon: Stop from the desktop, start the daemon externally (spawn `hutand` like the CLI does), the window leaves the stopped state without user action, a new terminal accepts typed input (marker echoed in its screen/history); `daemon::Start` while it already runs clears the state.
3. **R4-3** restart confirmation follows `daemon.restore_sessions` (read from the daemon settings the desktop already has; unknown → neutral text): respawn → current text; stopped → "… will be stopped. The new daemon lists them stopped (your setting “Leave them stopped”); start each again from its Restart action." Test both.
4. **R4-4** Escape closes an open Settings dropdown without changing the value, for every enum control (desktop and daemon pages); only a second Escape closes the sheet. Test on the Keyboard page dropdown after Down/Up.
5. **R4-5** numeric range hint uses the real rule: for `assistant.idle_stop_secs` show "0 (never) or at least 60" (add per-key hint text in `settings_daemon.rs`/labels where the daemon table's min does not express the rule); the field shows the daemon's refusal inline and keeps the typed value visible until corrected (does not silently snap back to 600).
6. **R4-6** the env/variables warning names the file that actually stores the values (daemon fields → daemon.toml; desktop `terminal.env` → settings.toml). The footer "Problems" counts daemon settings problems too (broken daemon.toml, field refusals, provider errors on the visible page) — "Problems · 1" with the first message, not "none".
7. **R4-7** provider errors in Models (and the Start sheet/direct chat where the same text appears): a plain first line ("Could not connect to r4-local at http://127.0.0.1:9. Check that the server is running and the address is right.") built from the error kind (connect / timeout / 401-403 auth / 404 model / other), with the technical text behind a "Details" disclosure. Pure mapping function with unit tests.

Labels in `settings_labels.rs`; `docs/design.md` touched where behaviour is described.
