## Change (summary of §6 TH-2)

1. **Icon pack registry** in `crates/settings/src/themes/`: `icon-theme.toml` manifests under `<data dir>/icon-themes/<id>/`, flat quoted semantic ids → relative SVG path, `extends = "builtin:phosphor"`, per-id fallback to the built-in, unknown ids warn, invalid packs listed disabled with diagnostics. GPUI-free.
2. **Safe SVG pipeline**: sanitizer that accepts only monochrome `currentColor` path artwork and refuses scripts, event attributes, entities, external URLs, CSS, data images, text/fonts, filters, `<use>`, oversized paths; path confinement (no traversal/symlink/non-regular files); size caps; content-addressed asset keys so a saved SVG really re-renders; bounded retired generations.
3. **Built-in `phosphor` pack** (Phosphor Regular, MIT, official `phosphor-icons/core` at a pinned revision recorded with the MIT notice) under `assets/icon-themes/phosphor/`, containing only the SVGs the id catalog uses; embedded and parsed by the same loader.
4. **Semantic cutover in `desktop`**: replace the `Icon` enum→Lucide file coupling with typed semantic ids (`panel.*`, `nav.*`, `action.*`, `state.*`, `session.*`, `vcs.*`, `dock.*`, `harness.*`, `brand.*`, `status.*`) resolved through the active icon pack; migrate every caller and the decorative text glyphs listed in chrome-v3 §5.3 (panel registrations, nav, titlebar, status items, session/project row glyphs, agent/task state glyphs); keep terminal text, user text, diff punctuation and keyboard symbols as text (record the exceptions). Agents ≠ Changes ≠ branches: distinct icons per §5.2/5.3. Remove obsolete Lucide SVGs and enum paths after callers migrate. The macOS menu-bar template image, app icon and notification identity stay fixed (documented exemption).
5. **Selection**: setting `appearance.icon_theme` (default `phosphor`), live switch, independent from color packs.
6. Docs: extend `docs/themes.md` with icon packs (layout, manifest, full id list generated from the registry with a drift test, author guidance, security rules), `docs/design.md` icon section.

## Tests
As in §6 TH-2 "Tests": registered-id coverage; default asset safety/serving/currentColor and license presence; omitting one id falls back to Phosphor for that id only; multiple ids → same file; unknown id warning; reload changes the SVG cache key and bytes; malicious SVG cases (scripts, events, entities, external URLs, CSS, data images, text/fonts, filter, use, huge paths); traversal/symlink/non-regular files; GPUI fixture proves a themed close/search/dock control renders the user's SVG with unchanged click/keyboard behaviour; switching icon theme changes no colors.
