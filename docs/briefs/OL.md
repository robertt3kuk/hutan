Decisions (the integrator's, from the user's request):
- Three columns like Orca: left sidebar 280 px (220–500), center tabs/splits, right sidebar 350 px (min 220) with a 36 px icon tab strip; 36 px titlebar row; 24 px status bar.
- **Assistant: off by default** (`assistant.enabled = false` for new users; existing users keep their value) and, when on, it is **a left-nav page**, shown inside the left sidebar in place of the project list (a tab of the left sidebar), never auto-placed in the right dock or the center.
- **History moves to the right sidebar** as "Agent Session History", the catalog from `history.sessions` (protocol 0.29, contract already on master in `crates/protocol/src/history.rs`, client `Connection::history_sessions` / `supports_history_sessions`). Full-text search stays (`history.search`) and is used when the user types a query and indexing is on — results ungrouped, ranked, like Orca's FTS mode.
- Privacy stays as decided: reading other agents' transcripts is opt-in (`history.enabled`). The History panel's off-state is one clear card: "Show your agent sessions" with the per-source checkboxes (Hutan, Claude Code, Codex, OMP) and an Enable button.

## OL-1 — daemon: the session catalog (crates `index`, `daemon`, docs; no protocol edits)

Implement `history.sessions` exactly per the DTO docs in `crates/protocol/src/history.rs`; advertise capability `history.sessions` in `conn.rs` (and update the capability-list test); remove the `Unsupported` router arm.
1. **Session summaries in the index** (`crates/index`): while the existing indexer reads Claude/Codex/OMP transcripts and Hutan blocks/chats, also fold a per-session summary row: source, session_key, provider title (Codex `session_index.jsonl` titles; OMP title records; Claude summary/ai-title records — see the Orca study §1 "title precedence"), first user prompt (≤ 2000 chars), latest 3 turns (role + one-line text ≤ 400 chars + ts), message count (user+assistant only), model of the last turn naming one, cwd, git branch if recorded, created/updated ms, transcript path, resume argv (existing validated resume logic; OMP resumes by absolute transcript path, as Orca does). Schema migration bump (the index is a cache: drop and rebuild is fine, as the existing version rule says). Incremental: reuse the existing per-file offsets/mtime so appends update the summary without rereading the file; a rewritten file is refolded. Bounded: skip records > 10 MiB, keep at most 3 latest turns in memory per session.
2. **Scan state**: files found per source, done count during a scan, scanning flag, finished time → `HistoryScanInfo`. `refresh: true` triggers a rescan of changed files and answers when it completes (bounded wait ≤ 10 s, then answer with `scanning: true`).
3. **Attribution and scopes** (daemon): map each row's cwd to the longest matching root among Hutan workspaces/projects (`workspace_id`); `workspace` scope = cwd inside any root of the workspace or its member projects; `project` scope = attributed id equals; `all` = no restriction. Filter = case-insensitive substrings, all terms required, over title/first prompt/latest/agent/model/branch/cwd/session_key; `repo:` = attributed project's name or root folder name; `path:` = cwd or transcript path; quoted values; filter > 2 KiB → no rows. Sort updated/created desc, ties by session_key. `matched` / `loaded` per the DTO doc. Hutan rows: chats and terminals of the daemon's own sessions (title = session title, `session_id` set).
4. Disabled indexing → `invalid_state` like `history.search`.
5. CLI: `hutan history sessions [--scope all|workspace|project] [--ws ID] [--filter TEXT] [--sort updated|created] [--limit N] [--refresh] [--json]` (table: agent, title, msgs, age, model, project) — terminal-safe output (strip control chars).
6. Docs: `docs/history-index.md` (catalog, fields, title precedence, scopes, performance), `docs/protocol.md` row already present (fix if behaviour differs).
Tests: index unit tests per source fixture (titles, first prompt, latest turns, counts, model, append-only update); daemon integration (scopes with two projects, filter incl. repo:/path:, sort, matched/loaded, refresh, disabled → invalid_state, Hutan rows); CLI test. Real-data smoke on a temp HUTAN_HOME **with history roots pointed at copies** — never read the user's real ~/.claude/~/.codex/~/.omp in tests; for a manual smoke the integrator decides.
