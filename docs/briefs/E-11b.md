## Scope
- `daemon`: `LspHub` — one server per (server binary, root), shared between the user's clients and agents; root detection by the **topmost** marker with a per-project override; a server is shared only when the root is inside its workspace folders; start on demand (first `doc.open` of a language in a trusted folder), idle stop, `max_servers`, restart with backoff (E-11a), state `starting|indexing|ready|failed|stopped` with reason; server processes and children in Resources as `service` nodes with RSS; kill on daemon exit.
- **Found, never fetched**: servers come from `daemon.toml [lsp.servers.<id>]` (command, args, env, root markers, languages, initialization options, idle stop, limits) and the login `PATH`; a missing server is a state `not_installed` with the exact install command and the setting to set. No network in this slice.
- **Trust**: one trust state per folder (`[lsp] trust = "ask"` default) covering server spawn, build scripts/proc macros and executable paths in workspace settings; an untrusted folder never spawns; trust decisions are user-only (`Access::UserOnly`), persisted, revocable; the request to trust is an attention item the desktop/CLI can answer. Say plainly in docs that rust-analyzer does not sandbox.
- Protocol: `doc.open/change/close` (bounded mirrors per §4.4, coalesced into E-11a's sync), `lsp.status`, `lsp.diagnostics {path? | workspace_id?}`, `lsp.hover/definition` (read), `lsp.restart/stop`, `lsp.trust {folder, decision}`; events `lsp.state`, `lsp.diagnostics`. `docs/protocol.md` § LSP.
- CLI: `hutan lsp [ls|status|restart|stop|trust FOLDER]`, `hutan diagnostics [PATH] [--json]` (works with no desktop attached: opens the files itself through `doc.open`).
- MCP: `diagnostics` (read-only: changed files plus their direct importers by default, a whole-project check only when asked; stale until the server is `ready`; filtered by workspace root). LSP is not offered as a references/grep replacement (lsp.md §6).
- Docs: new `docs/lsp.md` (servers, trust, config, limits, troubleshooting), `docs/resources.md`, `docs/control.md`, `docs/architecture.md`.
