- Date: 2026-10-30

## Context
The user asked (2026-10-30) for Mawas to be global across projects and to connect to the agents: "an agent over agents" that checks agents across workspaces, looks at what was done last time and analyses the flow. Today Mawas has one assistant per scope (Global in the Home folder, one per workspace), follows the active workspace, and — although `hutan mcp` already lets it read every workspace — has no consistent view of the agents (the reducer behind Today's rail lives in the desktop), no history window, no turn review, and a grant model (`control_grants`, key = method) under which one *Always allow `chat.send`* covers every agent in a workspace.

## Decision
1. **Global first; the workspace is a Focus.** Mawas Home opens the Global chat. A workspace is chosen as a *Focus* of a chat — a filter, and a source of memory notes and project instructions delivered as turn-boundary deltas — never as a different assistant or a different permission. No data is migrated: workspace chats and memory keep their ids and stay reachable (*Chats ▾*, `assistant.open {scope: workspace}`); `assistant.home_scope = "follow_workspace"` keeps today's behaviour. Focus is a property of a chat (`assistant.focus`, user-only), not a workspace kind: ADR 0017 decision 6 is neither needed nor blocked.
2. **The supervisor reads through new bounded, read-only requests and decides nothing.** `agents.board`, `agents.activity`, `agents.review`, `agents.stats` are classified Read, bounded (≤ 200 agents/events, ≤ 24 KiB), redacted, and carry their own *coverage* (what is exact, what is state only, what is not seen). Aggregates never turn *unconfirmed* into *idle*, label cost as an estimate, and say "not recorded" instead of zero. The board uses **one reducer**, lifted out of the desktop into a GPUI-free crate over `core` and `protocol`, so the rail, the CLI, MCP and the daemon cannot disagree.
3. **Acting on another agent is target-bound and always asked.** `chat.send`, `chat.send_now`, `chat.queue.add`, `agent.interrupt` and `task.review` are granted, if at all, per Mawas chat **and target session**; no workspace-wide grant exists for them. The approval shows the whole text, the target chat's journal records that the message came from Mawas with the user's approval, delivery goes through the daemon's queue and never the user's composer, Mawas cannot message a Mawas session, and `session.send_text` from Mawas into an agent that is `blocked` is refused. Mawas **never** answers an approval or a question, and never changes grants, settings or memory: `ask.suggest` attaches an advisory, labelled suggestion that the user's click turns into the user's own answer.
4. **Unattended means read-only.** Schedules and digests run the Advisor profile only. Nothing that needs an approval runs unattended before MW-10. A model digest waits for a spike that shows each harness's Advisor launch has no outbound network tool.
5. **Flow analysis stands on recorded data.** Time per turn and task, waits on the user, tokens and cost per project, recurring failures come from `chat_turns`, `approvals`, `questions`, `tasks`, `usage_turns`, `checkpoints` and `InsightTime`, within their retention (35 and 30 days for usage and checkpoints). Terminal agents have only their current state unless the user keeps `agent_state_log` (state and kind, redacted, 14 days; a setting).

## Consequences
- `docs/assistant.md` § Scope and § Desktop, `docs/control.md` § Mawas (grants) and `docs/design.md` § Mawas change with their slices; `docs/protocol.md` gains the requests above, each classified in `router.rs`'s exhaustive table in the commit that adds it, with golden fixtures.
- The reducer lift is a refactor with a parity test and lands before any request that uses it.
- Grants stored for the five methods of decision 3 before their slice are ignored (as grants for always-ask requests are today). Asking more often for these messages is the intended cost.
- A transcript is untrusted input to the model. The gate, not the model's judgement, is what limits an injected instruction; the prompt says so (R7 of the spike).
- Not decided here: the schedule service itself (MW-9), the restricted endpoint and sandbox (MW-10), skills and traces (MW-4, MW-7).
