# Changelog

Newest release first; add new entries at the top, under **Unreleased**. Older releases stay below, unchanged.

## Unreleased

### Added
- **Markdown preview**, no language server needed: a Markdown tab switches between *Source* and *Preview* (⇧⌘V), or *Open Preview to the Side* keeps a live page next to the text that follows your typing and scrolling — headings, lists with task boxes, tables, coloured code, quotes, local images, links that open files, headings or the browser. `editor.markdown_preview`, `editor.markdown_open`. The `marksman` server is now opt-in, so a README no longer asks for trust.
- **Pick fonts from a list**: the interface font (Appearance), the code font (Editing & keys: file tabs, previews' code, diffs and chat code) and the terminal font are each a searchable list of the fonts on this Mac, drawn in their own face (monospaced first for code and terminal, *Show all*, *System default* to go back to the theme's font, a preview line); changes apply at once, a typed name that isn't installed is warned about, and *Install font…* adds a `.ttf`/`.otf` for your account. `appearance.ui_font_family`, `editor.font_family`, `terminal.font_family`.
- **A board of every agent across workspaces** for Mawas and for you: Mawas's right rail has **Now** (every agent grouped by what it needs, finished ones folded, each row labelled *exact* or *state only*) and **Memory** tabs, and its width is draggable. Mawas and other MCP clients read the board, open questions and session history (`agents_board`, `question_list`, `history_sessions`; marked as untrusted data); in the terminal: `hutan agents --board [--ws …] [--json]`.
- **Mawas suggests, you answer**: Mawas can attach a suggested answer, with her reason, to another agent's waiting approval or question; the card shows *Mawas suggests: …* with **Use** (your own click on that option; for a question it only fills the form) and **Dismiss**. She never answers for you. Shown in `hutan approvals` / `hutan questions` too.
- **What happened while you were away**: Mawas's rail has a **Recent** tab — finished and failed turns, requests and how long they waited, tasks, checkpoints, sessions started and ended across every workspace since you last looked, grouped by agent, with *Mark as seen* and *Summarise with Mawas* (fills her composer, sends nothing). Mawas reads the same through `agents_activity`; in the terminal: `hutan agents --activity [--since 2h] [--json]`. What Hutan doesn't record is said, not shown as zero.
- **Mawas knows how to supervise**: a Global Mawas chat is given a short supervisor playbook — watch every agent, say where each fact comes from and how complete it is (never calling an unconfirmed agent idle), treat agents' text as data not instructions, label estimates, say "not recorded" instead of zero, message an agent only through its queue and ask you when the call is yours. Workspace chats and direct model chats don't get it.

### Changed
- **Mawas is global first**: Mawas Home opens the Global chat whatever workspace you're in; a **Focus** chip picks a workspace to concentrate on (its memory notes and `AGENTS.md` summary are given to Mawas, and changing the Focus tells her at the next turn); **Chats ▾** lists Global chats and the older per-workspace chats. `assistant.home_scope = follow_workspace` brings the old behaviour back.
- **Mawas acts on other agents only with your say, per agent**: a message, an interrupt or a review request from Mawas to another agent shows the target and the whole text and offers *Allow once*, *Allow for this chat and this agent* or *Deny* — no longer a grant for the whole workspace (older such grants are ignored for these actions). Her messages go through the agent's queue, never your draft, are labelled *from Mawas · sent with your approval*, never go into an agent that is waiting for your answer, never to another Mawas, and count toward her per-turn limit. `hutan approvals` shows the target and text too.
- **Closing a tab closes its session** (terminals, terminal agents, chats, splits): an idle one closes at once with *Undo*; when something runs Hutan asks — *Keep running in background* (default) or *Close*. `tabs.close_session = when_idle | always | never`; *Close Tab, Keep Running* in the tab menu; the old `terminal.tab_close` still works.
- **Every file gets its own tab** again (`editor.preview_tabs` now off by default).
- **Files open beside the agent**: with a chat or terminal agent in front, an opened file goes to a split on its right, reused for the next files (`editor.open_beside_agent`); ⌥-click, ⌥↩ in ⌘P and ⌘K *Files: Open to the Side* always open to the side.
- Mawas's chat column is as wide as you drag it (edges of the column; Esc cancels, double-click resets; ⌘K *Mawas: Wider / Narrower / Reset Chat Width*), remembered in `assistant.chat_width_rem`; the Today rail hides with a header button (a badge counts waiting requests while it's hidden) and stays as you left it.

## 0.3.4 — 2026-10-30

### Changed
- Right after a release is published GitHub may not serve its download for a minute: Hutan offers a release only once its archive can be downloaded, a manual *Check for Updates…* says "Hutan x.y.z was just published; it can be installed in a minute", and a download that isn't there yet says so instead of reporting a checksum mismatch.

### Upgrading
- **Test release** (a GitHub pre-release), the first you can install from inside the app: on 0.3.3, open the Hutan menu → *Check for Updates…*, then *Update now* → *Quit and Install*. With Homebrew: `brew update && brew upgrade --cask hutan` (or *Update now*, which runs it in a terminal you can watch). 0.3.2 and older still need one manual install.
- Protocol stays at **0.60**: no wire change since 0.3.3.
- No database schema change since 0.3.3: your sessions, history and settings open as they were.
- **Experimental — at your own risk:** remote hosts over SSH stay switched off until you turn them on in Settings ▸ Experimental (`experimental.remote_hosts`); they may change or break between releases. See `docs/remote.md`.

## 0.3.3 — 2026-10-29

### Added
- **Updates**: Hutan looks for a newer release on GitHub once a day (and on *Check for Updates…* in the Hutan menu, ⌘K, `hutan update check`) — one request, nothing else is sent; switch it off or pick the channel in Settings → General → Updates. A newer version shows as *Update to x.y.z* in the status bar with its release notes; *Update now* runs `brew upgrade` for a Homebrew install in a terminal you can watch, then *Relaunch*; *Skip this version* or *Later*. It never updates on its own, and agents can't update it.
- Updating an app you copied into Applications yourself (not through Homebrew): *Update now* downloads the release, checks its SHA-256 against both GitHub and the Homebrew tap, its signature, bundle id and version, shows the progress, then *Quit and Install* puts the old app in the Trash, the new one in its place and opens it. Anything that doesn't match stops the update and leaves your app as it was; a folder Hutan can't write to gets the command to run instead.

### Upgrading
- **Test release** (a GitHub pre-release). 0.3.2 and older cannot update themselves, so this is the **last manual install** for an app you copied into Applications by hand — replace it once yourself; from 0.3.4 on, *Update now* does it. With Homebrew: `brew update && brew upgrade --cask hutan`.
- Protocol **0.60** (an additive minor step: `update.status`, `update.check`, `update.install`, the `update.available` and `update.install` events, and the capability `update`).
- No database schema change since 0.3.2: your sessions, history and settings open as they were.

## 0.3.2 — 2026-10-29

### Added
- Agents in terminals are recognised: when OMP, Claude Code, Codex (and others) run in a terminal, the tab and the sidebar row show the agent's own icon instead of `>_`, the **session takes the agent's name** (OMP's session title, without the `π` prefix; a name you set yourself stays, with the agent's title under it), and the state shows — a spinner while it works, a bell when it waits for you (the question appears under the row and in Requests), a cross on error, a check when done. A bell also marks a tab that rang or notified while out of sight. Read from OMP's status signal (OSC 7501), the window title and the running process — no hooks needed; `hutan ls` has an AGENT column.
- **Fork a chat from any turn**: *Fork…* in each turn's footer, on a message's hover bar, in the session menu, ⌘K *Chat: Fork from Here* and ⑂ on a sidebar card. The popover says honestly where the agent can cut (exact turn, latest turn only, or a summary — you choose, never silently), *Where*: this folder or a **new worktree with that turn's files** (remembered), *Restore files to this turn*, *Archive the original*. Also `hutan chat fork`, MCP `chat_fork`.
- **Extra folders in a session**: a folders chip in the chat header and on terminal agents opens *Folders in this session* — add a folder (it says how this agent takes it: at once, from the next turn, after a restart, or typed `/add-dir …` for you to confirm in a running terminal agent), remove one, or *Restart with this folder*; the ＋ menu and ⌘K have *Add Folder to This Workspace…* and *Add Folder to the Focused Session…*; Files shows the session's extra folders as roots. Also `hutan chat dirs add|remove|list`, `--dir` on `hutan chat new` / `hutan new`. Only you can add folders, never an agent.
- **Context panel** on the right (after Files and Changes): for the agent in view, how full its context is (with the agent's own numbers), *Measure context* for the breakdown by category when Claude Code or OMP can give it (the measurement never shows up in the chat), fill by turn, every turn with *Fork…* and *Rewind…*, tools used, files touched (open or diff), tokens in/out/cache, cost where the agent reports it, and time; it says plainly what an agent doesn't report (Codex: tokens only). Also `hutan chat insight SESSION [--measure]`, MCP `agent_insight`.
- Usage in the status bar: one small ring per agent with its glyph inside, filling with the share of its tightest limit (amber from 80 %, red from 95 %, with the number shown); hover lists every window with reset times and today's/this week's use; click opens the Agents page. Shown only once an agent has reported a limit; Settings → Status bar → *Usage limits* (rings, words or hidden).

## 0.3.1 — 2026-10-28

### Added
- File operations in the daemon (groundwork for the file explorer): create, rename, move, copy and **Trash** (never permanent delete) with undo tickets, confined to the project like writes; `hutan fs mkdir|touch|mv|cp|trash|restore`. An agent's Trash always asks, with no session-wide grant.
- Soft wrap in the editor: Markdown and plain text wrap at the window by default, code doesn't (`editor.soft_wrap = auto|off|viewport|column`, `editor.wrap_column`, per language `languages.<name>.soft_wrap`); ⌥Z or View → Toggle Soft Wrap per tab, a *Wrap* status item; ↑/↓, Home/End and selections follow wrapped rows; Vim `j`/`k` stay on lines, `gj`/`gk`/`g0`/`g$` move by row.
- File explorer, step 1: a new window opens the right side on **Files**; folders first in natural order, single-folder chains on one row, indent guides, a scrollbar, Refresh and Collapse all, hidden and ignored files toggled separately in ⋯, Home/End/PgUp/PgDn and ⌘←/⌘→, open folders remembered per project and across restarts, file-type icons; a built-in **Explorer left** preset (⌘⇧4) puts Files in the left sidebar. Big trees stay fast (a 100 000-row tree updates a folder in 0.2 ms).
- File explorer, step 2 — it changes things now: New File / New Folder (header buttons, ⌘N / ⌥⌘N), Rename (F2, the name without its extension selected), Duplicate (⌘D), Cut / Copy / Paste (also files copied in Finder), drag to move (⌥ copies), **Move to Trash** (⌘⌫, always asks and lists unsaved tabs and agents working there), and ⌘Z / ⇧⌘Z in the tree. Open tabs follow a rename or move with their unsaved text and undo history.
- File explorer, step 3: select several rows (⇧-click, ⌘-click, ⇧↑↓) and act on all of them; a full row menu with key hints — Open to the Side, Reveal in Finder, Open in Terminal, Attach to Chat, Find in Folder, Show File History, Copy Path / Relative Path (⌥⌘C / ⌥⇧⌘C), **Compare** two files or a file with HEAD; drag rows onto a chat or a terminal to type their paths.
- File explorer, step 4: **filter as you type** — start typing in the tree (or ⌘F) and it shows matching files as a folded tree with the matched letters marked, instantly from what's loaded and then from the whole project; ↓ to walk the results, Esc to get the tree back as it was; *Filter in this Folder* and the "first 5 000" row filter one folder; `panels.files.filter_mode = highlight` marks matches without hiding the rest.
- File explorer, step 5: **Open Editors** (with two or more file tabs: unsaved dot, close button) and **Changed by agents** (◆, who changed what and how many hunks, newest first) above the tree; error/warning counts on files and folders; agent marks in the tree; the Changes rail icon counts uncommitted files; a *working* dot on scope chips while an agent works there.
- File explorer, step 6: the scope chip switches the tree to another worktree or project without moving the window; *Show the Whole Workspace* (`panels.files.roots = workspace`) stacks every project of the workspace as one tree (filter, marks, sections and drag work across them); drop files from Finder onto a folder to copy them in (one undo step, never overwrites).
- A worktree nobody works in can be browsed and edited too (before, Files said "outside the workspace roots" until a session ran there).
- Git change marks in the editor gutter (added / modified / removed against the index): click a mark for a peek with *Revert hunk* and *Stage hunk*, ⌥F5/⇧⌥F5 or Vim `]c`/`[c` step through changes (`editor.git_gutter`).
- Scrollbars everywhere: the editor (with ticks for problems, git changes and find matches), the terminal scrollback, chat and Mawas, Search, Problems, Files, Changes, the palette, the Start and Settings sheets and other lists — overlay bars that fade like macOS, draggable, click the track to page; follows the system "Show scroll bars" setting or `appearance.scrollbars = always|scrolling`.

## 0.3.0 — 2026-10-26

### Added
- Find in a terminal: ⌘F in a terminal searches its whole scrollback in the daemon (wrapped lines joined, case and regex options, optionally only the selected block's output), ⌘G / ⌘⇧G step, matches highlighted; `hutan terminal search`.
- Instruction files: an **Instructions** panel lists the files each agent reads (AGENTS.md, CLAUDE.md, OMP's rules; project and user level) and which agent reads which; *Share one file with every agent…* makes AGENTS.md the one file (CLAUDE.md imports it) after showing exactly what it writes, with Undo; Mawas knows how the project's AGENTS.md begins.
- Mawas's folder: Files, Search and Problems show `~/Hutan` at Home and follow Mawas's scope while Mawas Home is in front; Mawas's ⋯ says where she works with *Show Folder in Files*, *Open in Finder*, *Open Terminal Here*; *Track changes in this folder…* turns the folder into a git repository (after a confirm, nothing leaves the machine) so Changes, checkpoints and *Rewind…* work for what Mawas writes; `hutan project git-init`. Finish without a remote commits only.
- Usage and limits: the Agents page has a **Usage** section — each harness's limit windows with reset times (Codex and Claude Code as they report them, OMP via `omp usage`), tokens today and this week, costs marked as estimates; an optional status item (`Codex 72% · resets 3h`); a warning at 80 % and 95 % of a limit, once per window; `hutan usage`, MCP `usage_summary`.
- Mawas memory as files: the memory is mirrored as Markdown in `~/Hutan/.mawas/memory/` (and, if you turn it on, `<project>/.hutan/memory/`); editing a file proposes the change for your approval, never applies it silently; `hutan memory export|import|files` and Export/Import in the Memory panel; in a tracked folder the files are versioned with git like anything else.
- Git history and blame: *Toggle Blame* shows author · date · message per hunk in the editor gutter (unsaved lines show as uncommitted; optional inline blame for the caret line), *Show File History* lists a file's commits across renames with their diffs and *Open at this revision*, and Changes has a **History** segment for the checkout's recent commits; `hutan git log|blame|show`, MCP `git_log`, `git_blame`.
- Quick terminal: a global shortcut (⌃⇧`, configurable) drops a terminal down from the top of the screen over any app, full-screen Spaces included; the shell is kept between shows, ⌘T adds tabs, Escape or the shortcut hides it, ⌘⇧↩ moves the tab into the main window.
- Paste images into a terminal: ⌘V with an image on the clipboard saves it as a PNG in the session's scratch folder (removed with the session) and types its path, escaped the way Claude Code, Codex and OMP read it; a toast offers *Reveal*. `terminal.paste_images` turns it off.
- User hooks: `[[hooks]]` in `daemon.toml` run your own commands when a turn finishes or fails, an approval is requested, attention changes, a session exits, a task is done or a Finish completes (filters by harness/project/workspace; redacted JSON payload on stdin and `HUTAN_EVENT_*` env; bounded, with timeouts) — e.g. a phone notification via ntfy; Settings → Automation shows hooks, runs and *Run test*; `hutan hooks list|test|log`. Agents can't add or run them.
- One Changes list across a workspace: with several repositories or worktrees, the Changes tab switches between *This checkout* and *All in workspace*, grouped by `repo · branch` with counts and *Finish…* per group; project rows in the sidebar show how many files are uncommitted; `changes.default_scope`.
- Worktree setup and cleanup: `.hutan/worktree.toml` copies gitignored files (`.env`…) into a new worktree and runs its setup commands in a visible *Setup* terminal (repository commands run only after you trust their exact text; agents can't); rows show *Setting up…* / *Setup failed*; teardown before removal; *Worktree: Clean Up…* and `hutan wt prune` list merged or idle worktrees with nothing uncommitted — never removed in the background; `hutan wt create --no-setup`, `hutan wt setup`.
- Several accounts per harness (work and personal): Settings → Accounts adds named accounts for Codex, Claude Code and OMP, each a separate harness config folder whose login is the harness's own (Hutan still never reads tokens); defaults per harness and per project, an Account row in the Start sheet, the account in the chat header and per-account usage windows; `hutan account list|add|remove|default|login`, `hutan chat new --account`.
- Safety presets: the Start sheet has a **Safety** row — *Ask* · *Contained* (no questions inside the harness's own sandbox: Codex workspace-write with network off, Claude Code's Bash sandbox) · *Read-only* · *Full access* — offering only what each harness can honour (OMP has no OS sandbox, so *Contained* is off for it, with the reason); the chat header shows what the harness actually reports, not what was asked; `[launcher] safety`, `hutan chat new --safety`.
- Contain: terminals and OMP chats can run inside a macOS Seatbelt boundary — writes only in the checkout (git hooks and config stay read-only), `~/.ssh`-style folders and the Keychain unreadable, network on or off; a self-test at daemon start refuses rather than run uncontained; OMP's *Contained* preset now works; a chip says what the boundary allows; `hutan new --contain [--network off]`, `[sandbox]` in `daemon.toml`.
- Partial commits: stage and unstage files and single hunks (even lines) in Changes — a *Review · Stage* toggle above the diff, *Stage hunk* `s`, *Unstage hunk* `u`, *Discard hunk…* `x` (asks first, with Undo through a checkpoint), `j`/`k` between hunks; *Commit staged…* and Finish's *Commit staged only* commit exactly the index; `hutan wt stage|unstage|discard`, `hutan wt diff --hunks`, `hutan finish --staged`. Agents can't stage, discard or commit.
- **Experimental — at your own risk:** remote hosts over SSH. Off by default; turn on in Settings ▸ Experimental (`experimental.remote_hosts`). Then `hutan --host NAME <command>` drives the Hutan of another Mac through your own `ssh` (no new port, no listener; SSH is the authentication), `hutan host add|list|test|remove|forward` manage profiles. It may change or break between releases, and anyone who can SSH into that host's account gets the same control over its Hutan. See `docs/remote.md`.

- One button system everywhere: primary / secondary / ghost / destructive / link and icon buttons in two sizes with hover and press fades, keyboard-only focus ring, disabled and loading states; one primary per surface, Cancel before the primary, Return confirms and Esc cancels — destructive confirms are never the default; sentence-case, verb-first labels.
- The status bar says something again: the background service's state always (`● hutand`, `○ Stopped · Start`, `▲ Can't start · Details` — click for the daemon popover), the project and branch you work in, `◌ N working` while agents run, and the requests that wait.

### Agents and chat
- Checkpoints: every agent turn that changes files in a git checkout is snapshotted in hidden git refs. *Rewind…* on the turn shows exactly which files go back, flags files edited since, and restores only what you tick; *Undo* reverts the restore, also after a restart. `hutan checkpoint ls|diff|restore|undo|rm`.
- Message queue: typing while the agent works queues the message (editable chips); ⌃↩ sends now (Codex steers the running turn, other agents are interrupted first); Stop clears or keeps the queue.
- Attention that clears: an agent that is working is never shown as needing you; only turns that changed files ask for review; looking at the result quiets it; Finish closes it.
- Finish = commit and push from the Changes view (no PR), with staged/unstaged markers and a message pre-filled from the changed files (`Update app.py and store.rs`) plus one line per agent that made them.
- A session whose finished work you have seen goes back to its own state with a small *Changes to review* link, instead of staying in *Needs you*.
- Clearer approvals (one primary *Allow once*), chat retry (a rate-limited turn counts down to *Retry now*), mute per session, the agent's real mode shown; drafts survive, a context meter in the chat header, mark unread and snooze.
- Mawas keeps a curated memory: entries you approve, with revisions; `hutan memory`.
- Models: display names everywhere (also after a restart, kept offline); pickers mark the current model, order by family and newest first, and tell apart same-named variants.
- Language servers: the Problems panel shows each server's state with Restart for a failed one; the trust bar names every server the folder would start and one answer covers the folder; a rustup `rust-analyzer` without the component is reported as not installed with the install command.

### Reliability
- The app manages its background service: it knows which build answers, restarts an idle older or foreign service onto its own binary (asks first when sessions are live, never replaces a newer one), retries a failing start with backoff and stops after three identical failures with a *Retry*, and a stop from any place (app, menu bar item, `hutan daemon stop`) stays stopped until you start it. Start-at-login is re-registered when the app moved.
- Daemon menu: Start/Stop/Restart/Status are enabled whenever they can act (also with no Hutan window in front); recovery items show only while their failure is current; *Start Daemon at Login* no longer claims the launch agent is missing when it simply was never registered.
- When the background service cannot start, Hutan says why and offers the fitting action: data written by a newer Hutan → update command or *Start with empty data…* (old data kept in `backups/`); a stuck service → show or stop that process; anything else → logs and details. `hutan daemon status|why|reset-data`.
- Many flaky tests fixed at their cause; a guard fails the test run if a test leaves a daemon behind.
- File watching no longer misses a write made between reading a file and watching it.
